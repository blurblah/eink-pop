## 선택한 환경과 검증 방법

- 빌드 도구: 기존 Arduino IDE 번들의 Arduino CLI 1.5.1을 사용합니다. 별도 PlatformIO는 설치하지 않습니다.
- 코어: `esp32:esp32@2.0.17`을 프로젝트 내부에 설치합니다. 현재 전역 설치된 3.3.7은 보존합니다. 제조사 문서의 CLI 예시와 같은 버전을 선택하며, 3.3.7의 호환 여부는 이번 검증의 성공 조건이 아닙니다.
- 환경 분리: `.local/arduino-cli.yaml`의 `directories.data`, `directories.downloads`, `directories.user`, `build_cache.path`를 각각 `.local/arduino/` 아래의 절대 경로로 지정하고 모든 CLI 호출에 해당 설정을 명시합니다. 실제 적용 설정과 전역 코어 버전을 설치 전후 비교합니다. [Arduino CLI 설정 근거](https://docs.arduino.cc/arduino-cli/configuration/)
- 드라이버: 공식 `LilyGo-EPD47`의 `esp32s3` 소스를 `.local/libraries/LilyGo-EPD47/`에 확보하고 사용할 커밋을 고정해 문서에 기록합니다. 빌드할 때 이 라이브러리 경로를 명시합니다. 웹 커밋 이력의 확인값은 `3607e73ba8b84f10e1595511894df52fb008b82a`이지만 캐시일 수 있으므로 다운로드 시 실제 원격 상태를 재조회합니다. [공식 커밋 이력](https://github.com/Xinyuan-LilyGO/LilyGo-EPD47/commits/esp32s3/)
- 외부 라이브러리: `drawImages` 자체는 SensorLib·Button2·ArduinoJson을 직접 사용하지 않으므로 먼저 드라이버와 코어만으로 컴파일합니다. 제조사 메타데이터의 의존성이 실제로 요구되면 CLI 안내에 있는 `SensorLib@0.3.1`, `Button2@2.3.2`, `ArduinoJson@7.4.2`를 동일한 프로젝트 전용 환경에 설치하고 이유를 기록합니다. [제조사 개발 안내](https://github.com/Xinyuan-LilyGO/LilyGo-EPD47/tree/esp32s3)
- 보드 설정: `ESP32S3 Dev Module`, Flash 16MB, QIO 80MHz, OPI PSRAM, Hardware CDC and JTAG, USB CDC On Boot 활성화를 기준으로 합니다. 설치한 2.0.17의 `board details` 및 공식 예제 설정과 대조한 FQBN을 기록합니다. [공식 drawImages 설정](https://github.com/Xinyuan-LilyGO/LilyGo-EPD47/blob/esp32s3/examples/drawImages/drawImages.ino)
- 메모리 확인: USB 목록만으로 칩과 메모리 크기를 확정하지 않습니다. 승인 후 칩·Flash 조회를 수행하고, PSRAM은 시험 펌웨어의 런타임 조회·버퍼 할당 결과로 별도 확인합니다.
- 백업: 실제 검출한 Flash 전체를 주소 0부터 읽고 파일 크기와 SHA-256을 확인합니다. 복원 도구 버전·대상 재확인·주소·명령을 기록합니다. 백업이나 호환 복구 수단을 확보하지 못하면 업로드하지 않습니다.
- 표시 시험: 부팅당 공식 이미지 3장만 순차 출력하고 각 출력 후 패널 전원을 끕니다. 마지막 이미지를 유지하며 이후 화면 갱신은 하지 않습니다. 출력 진행·메모리 정보·종료 로그를 남깁니다. 무한 이미지 반복, 딥슬립 자동 재시작, 부분 갱신 속도 시험은 추가하지 않습니다.
- 판정: 빌드 성공, 업로드 성공, 장치 종료 로그, 사용자의 실제 이미지 관찰을 각각 구분해 기록합니다. 화면 관찰 전에는 전체 계획을 완료로 표시하지 않습니다.
