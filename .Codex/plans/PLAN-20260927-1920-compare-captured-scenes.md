## 요청 사항

기존 오프라인 분석에 이어 실제 게임의 이동·도약·화면 전환 장면을 수집하고 표시 후보를 비교한다. 개입이 필요한 경우만 사용자에게 요청한다.

## 성공 조건

- [x] 게임의 기존 데모 또는 저장된 리플레이를 제한 실행하고 최신 PPM을 수집한다. 실행·종료·누락 번호·출처를 기록한다.
- [x] 실제 확보된 장면을 확인하고 없는 장면을 확보했다고 주장하지 않는다.
- [x] 기존 Bayer4와 Bayer2, 단순 문턱값 흑백을 같은 밝기·생명력 보정으로 비교한다. 기존 USB 전송기와 펌웨어는 변경하지 않는다.
- [x] 수집 명세·파일 해시 검증, 후보별 변화 픽셀·행 범위·모델 지원 비율을 계산한다. 예측 불가능한 시간과 잔상·깜빡임은 명시한다.
- [x] 원본과 후보의 동기화된 브라우저 재생·프레임 탐색을 제공한다. 수집 시각 기반 재생은 패널 속도 예측과 구분한다.
- [x] 관련 테스트·실제 보고서·화면 검증·문서·로컬 커밋을 마친다. push 없음.

## 가정 및 제약

- 사용자 키보드를 대신 조작하지 않고 기존 데모/리플레이를 먼저 사용한다. 최대30초씩, 총3회 이내 수집한다.
- 자동 데모·리플레이에서도 필요한 장면을 얻지 못하면 확보한 장면까지만 기록하고 필요 시 사용자 조작을 요청한다.
- 원본과 게임 산출물은 artifacts에 보존한다. 기존 저장 파일·게임 설정을 바꾸지 않는다.
- 새로운 파형이나 드라이버 성능 모델을 도입하지 않는다. 현재11표본 모델을 범위 안에서만 사용한다.
- 게임·드라이버·USB 제품 경로 변경은 범위 밖이다.

## 위험 및 롤백

단순 흑백은 중간톤을 잃으며 점무늬 제거가 품질 개선을 보장하지 않는다. 변화 픽셀 감소를 속도 향상으로 환산하지 않는다. 별도 도구이므로 신규 파일을 되돌리면 기존 경로에는 영향이 없다. 실행한 게임 자식만 정상 종료하고 실패 시 해당 자식만 회수한다.
