## 요청 사항

> Mac 대신 다른 게임 실행 보드를 넣을 예정인데 지금 깜빡임 개선이 의미 있는지 설명하고, 의미가 있다면 진행한다.

현재 e-paper·ESP32 화면 구동부를 유지하고 게임 실행 보드를 바꾸는 것으로 가정한다. 지난 16계조 시험은 화면 처리 평균 1.911초 중 전체 지우기 1.362초가 들었다. 전송 장치와 무관한 화면 구동 병목이므로 바뀐 픽셀만 구동하는 실험은 재사용 가치가 있다. 사용자에게 이 이유와 흑백 점무늬의 화질 타협을 설명했다. 최신 “있다면 설명해주고 진행”을 이 범위의 명시적 실행 승인으로 기록한다. 계획 생성·열기 후 구현하며 동일 승인을 다시 요청하지 않는다.

## 성공 조건

- [x] 고정 좌표 4×4 점무늬로 명암을 표현하고 기존 밝기·생명력 보정 규칙을 유지한다. 동일 RGB 입력은 항상 동일 비트맵을 만든다.
- [x] USB v3의 320×200 1bpp(8,000바이트, MSB 우선, 1=검정)를 호스트와 펌웨어가 일치하게 처리한다. v1/v2를 거부한다.
- [x] 최초 전체 지우기 이후 바뀐 픽셀만 기존 두 패스로 처리한다. 무변경은 패널 전원을 켜지 않는다. 새 파형·드라이버 수정은 없다.
- [x] 실제 제품 변환·전송 회귀와 스케치 포함 native 검증으로 픽셀 전환·마스크·경계·종료·ACK 보호를 확인한다.
- [x] ESP32-S3 빌드와 대상 재식별 뒤 업로드·READY까지 검증한다. 연결되지 않았으면 준비 결과와 미실행 범위를 기록한다.
- [ ] 사용자 관찰 준비 후 실제 게임 최대 12장을 시험하고 큰 깜빡임·이동 식별·잔상·생명력 가독성을 기록한다. 실물 평가 전에는 개선 완료라고 판정하지 않는다.
- [x] 변경을 로컬 커밋하고 push하지 않는다.

## 가정 및 제약

- 현재 패널과 화면 구동부를 유지한다. 다른 패널·컨트롤러로 바꾸면 표시 방식의 원칙은 참고할 수 있으나 파형·성능은 다시 검증해야 한다.
- Mac은 현재 프레임 공급원으로만 사용한다. USB 최적화·새 게임 보드 포팅·배선은 범위 밖이다.
- 회색 단계는 현재 승인된 보정과 같은 값으로 구한 후 Bayer 4×4 행렬과 비교한다. 시간·프레임 번호에 따라 패턴을 바꾸지 않는다. 0/15는 완전 검정/흰색이다.
- 현재 v2 회색 경로는 Git 이력과 기존 바이너리에 보존하고, 이번 v3는 흑백 차분만 수행한다. 호스트와 펌웨어를 함께 사용한다.
- v1의 검증된 차분 마스크를 재사용하되 현재 v2의 ACK 연결 확인·flush와 시간 제한을 유지한다. clear_us/white_us/black_us를 따로 기록한다.
- 최초 약 20초 지연 검사, 최대 12장, 최초 패널 구동부터 30초 이후 새 갱신 금지, RX 5초, 종료 후 10초 관찰을 유지한다. 종료 때 마지막 그림을 유지하고 패널 구동 전원은 끈다.
- 자동 장시간 반복이나 미검증 파형 단축은 하지 않는다. 잔상과 게임 적합성은 실물 관찰이 필요하며 속도 향상을 보장하지 않는다.
- 보드 화면 시험은 사용자 준비 응답 후 시작한다. 실제 게임 시험은 창 전환 시간을 60초 제공한다.

## 실행 계획

- [x] 1. 호스트 변환과 펌웨어 차분을 구현 → 고정 명암/끝값/비트 경계/극성/변화 행/무변경/이전 버전 거부 검증.

- [x] 3. 독립 코드 검토와 ESP32 빌드 → 스케치 일치·드라이버 경로·해시·기존 산출물 보존.
- [x] 4. 대상 재확인·업로드·READY 관찰 → 화면 출력은 사용자 준비 후 별도 제한 시험, ACK/DONE/종료 검증.
- [x] 5. 결과와 한계 기록·로컬 커밋 → Git 상태 확인, push 없음.

## 위험 및 롤백

점무늬는 화질을 거칠게 만들고 움직이는 부분의 변화 픽셀·잔상을 늘릴 수 있다. 두 패스 사이 인물 일부가 잠시 분리돼 보일 수 있다. 전체 깜빡임 감소가 플레이 가능성을 보장하지 않는다. 문제가 있으면 추가 반복을 중단하고 기존 검증된 전체 지우기 한 번으로 잔상 정리를 별도 진행한다. 이전 v2 호스트·펌웨어와 바이너리를 함께 복원할 수 있도록 이력을 보존한다. 패널·전압·구동 파형은 바꾸지 않는다.

## 실행 기록

- 시작 전 상위 작업 트리 clean. 관련 계획·현재 코드·이전 v1 차분 구현을 확인했다. 프로젝트 문서와 기존 테스트가 절차를 보존하므로 별도 새 스킬은 만들지 않는다.
- 계획 생성 직후 `code`로 열었다(exit0, macOS codesign 진단1줄). 사용자 승인 범위에 따라 구현했다. 하위 두 저장소는 수정하지 않았다.
- 호스트29개, 실제 스케치 native47개(C++11 경고 오류화·ASan/UBSan) 통과. 독립 검토에서 오래된 설정 로그를 발견해 수정하고 해당 로그 검증을 추가, native47개 재통과.
- source46 실제 게임 화면을 제품 변환으로 미리보기 생성. 비트맵 SHA `f83f3e2a9d1218012b33216b96a66541c50310426ab5a89dd5aa5bddfc1991ea`.
