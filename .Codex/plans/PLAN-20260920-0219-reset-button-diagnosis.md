## 가정 및 제약

- 현재 앱은 `usb_frame`, 상위 구현 `207ed1e`, 실제 앱 SHA `dfc935d48f86e67f66fc57136c6a15ffb7cce97109cc95447b514f7b274d74a0`이다. 첫 게임 FRAME은 아직 보내지 않았다.
- 이 앱은 부팅에서 화면을 지우지 않고 READY 대기한다. 일반 GPIO 버튼 이벤트도 구현하지 않았다. 화면에 사각형이 남아 있다는 사실만으로 리셋 실패를 판단할 수 없다.
- 현재 장치와 연결 권한을 다시 확인한다. 호스트 sandbox 접근 오류를 보드 고장으로 해석하지 않는다.
- 우선 Flash 쓰기·패널 갱신 없이 직렬 수신만 한다. 직렬 열기에서는 기존 RTS 해제·DTR 설정을 사용하므로 사용자 조작 이전 상태를 먼저 확보한다.
- 적용할 전용 스킬은 없으며 기존 문서·실제 소스·제조사 자료로 확인한다.

## 위험 및 롤백

리셋은 실행 상태를 초기화하지만 e-paper를 자동으로 지우지 않는다. BOOT와 RST를 같이 누르면 다운로드 모드에 들어갈 수 있으므로 최초 확인은 RST 단독으로 한다. 수신 로그만으로 물리 버튼 누름을 식별하지 못하면 고장으로 단정하지 않는다. 현재 firmware·백업은 유지하며 관찰 프로세스를 종료하고 직렬 포트를 닫는다.

## 실행 기록

최초 기본 sandbox에서 직렬 열기가 `EPERM`으로 거부돼 관찰을 닫았다. 같은 장치는 CLI 조회에서 인식됐으며, 승인된 장치 접근 권한으로 다시 열어 02:18:35 KST에 READY를 확인했다. 첫 줄은 기존 전송의 잘린 부분이었고 이후 완전한 READY가 들어왔다. 화면 START·픽셀은 보내지 않았으며 관찰이 열린 뒤 사용자에게 RST 단독 한 번을 요청했다.

02:19:16에 직렬 끊김, 02:19:17에 동일 장치 재연결과 READY가 관측됐다. 사용자가 물리 RST를 눌렀다는 답변과 시각은 확보하지 않았으므로 이를 버튼 정상 판정으로 기록하지 않는다. 이후 사용자가 “이 문제라고 하는건 잔상 남는 문제”라고 정정했다. 요청을 잘못 해석한 버튼 진단을 중단하고 02:20:37에 직렬 관찰을 닫았다. 총 122.744초, 호스트 payload 송신 0회, Flash·패널 구동 0회다. 잔상 확인은 기존 USB 계획의 선행 흰 화면 한 장 시험으로 수행한다.
