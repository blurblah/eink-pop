## 요청 사항

이전 PoP 잔상을 검증된 제조사 전체 지우기로 정리하고, 깨끗한 배경에서 새 드라이버의 움직임·새 잔상을 구분해 확인한다. 구현·빌드·업로드·기록은 추가 승인 없이 이어가고 실물 관찰에 필요한 응답만 요청한다.

## 성공 조건

- [x] 해시가 검증된 제조사 콜백 앱으로 흰 화면 한 장을 처리한다. 전체 정리 1회, 추가 흑/백 그림 0회, DONE 후 10초 무출력을 확인한다.
- [x] 사용자가 과거 게임·정지 패턴 흔적 제거 여부를 확인한다. 제거되지 않았다면 추가 반복 정리·이동은 하지 않고 원인을 분석한다.
- [x] 이미 검증된 Painter v2 앱을 다시 올려 패널 미접근 READY를 확인한다.
- [ ] 깨끗한 배경이 확인되면 관찰 안내 후 MOVE 최대 12장을 한 번 실행한다. 완료 주기·프레임별 시간·전원OFF·종료 후 10초와 실제 움직임/잔상을 확인한다.
- [ ] 결과와 한계를 로컬 커밋한다. push하지 않는다.

## 가정 및 제약

- 제조사 드라이버 9b8dcdb의 전체 지우기는 과거 f1607da에서 잔상을 없앤 동일 함수다. 이후 콜백 계약 수정은 이력에 구분한다.
- Painter는 드라이버 7544e2d, 앱 v2 SHA-256 6e61fb81a86098889e69d73e574c8c3af7b96aeff7ad6b2346bdc260d3c74db5를 그대로 사용한다. 파형·반복 횟수·100ms 프레임 간 대기를 변경하지 않는다.
- 개별 앱으로 번갈아 실행하며 두 드라이버를 동시에 초기화하지 않는다.
- 잔상 제거는 사용자 관찰로 확인한다. 앱 전원OFF나 완료 로그만으로 광학 상태를 추정하지 않는다.
- 사용자 관찰을 기다리는 동안 패널을 건드리지 않는 후속 준비를 계속한다. 별도 준비 확인을 관성적으로 반복하지 않는다.

## 영향 범위

- `.local/`: 이번 전체 정리·Painter 재업로드·이동 관찰 도구. 기존 호스트 프로토콜 재사용.
- `artifacts/`: 별도 실행 디렉터리, 입력·원본 TX/RX·장치 식별·검증 결과. 기존 제외 규칙 유지.
- 문서·계획: 결과와 현재 보드 상태를 기록한다. 펌웨어·하위 드라이버 소스 변경은 예정하지 않는다.

## 실행 계획

- [x] 1. 백업·빌드·입력·현재 장치 확인 → 흰색 8000바이트 및 CRC/패킷 검증 준비.
- [x] 2. 제조사 앱 단일 업로드·흰 화면 한 장 → 해시 4구간·delay 검사·clear/white/black 시간·ACK/DONE 검증.
- [x] 3. 사용자 잔상 관찰과 Painter READY 복귀를 병행 → 흰 화면 유지와 패널 시작 0회.
- [ ] 4. MOVE 관찰 도구의 정상/중복/누락/오류·시간 한도 검증 → 최대 12프레임 단일 실행과 기록.

## 위험 및 롤백

기존 출고 백업·제조사 앱·Painter 앱을 해시로 확인하고 보존한다. 오류·미종료에는 다운로드 모드로 정지하고 자동 재시험하지 않는다. 정리 1회로 제거되지 않으면 임의 파형 강화·반복을 진행하지 않는다. 파일은 작업 커밋으로 되돌릴 수 있다.

## 실행 기록

- 직전 정지 패턴은 다 보이고 멈췄으나 예전 게임 잔상이 남았다. 새 드라이버 전체 HARD clear는 223.417ms였고 정상 반환했지만 광학 정리 성공은 아니었다.

- 제조사 전체 정리 1.324097초, 추가 흑/백 그림 0회, 실제 송신 START+흰 FRAME 8049바이트·CRC/ACK/DONE 검증. 이후 10.005222초 무응답.
- 사용자 “흔적이 모두 사라졌어요” 확인. Painter v2 재업로드·READY 중 패널 시작 없음.
- 관찰 예고 15초 후 MOVE 1회. 12장 각 1주기, 후속 display 평균 70.347ms, 완료 간격 평균 185ms(100ms 대기 포함). 2.402498초에 DONE·전원OFF, 이후 10.047721초 추가 로그 없음. 포트 닫힘, terminal 상태.
- 이동 호스트 로그 검사 13사례 통과. 사용자 움직임·새 잔상·깜빡임 관찰 대기 중이다.
