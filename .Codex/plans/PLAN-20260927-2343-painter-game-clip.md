## 요청 사항

같은 사각형 시험의 반복을 끝내고 실제 게임 연속 프레임에서 고속 드라이버의 속도·명도·잔상을 확인한다. 구현·오프라인 검증·업로드는 자율 진행하고 실물 관찰이 필요한 때만 요청한다.

## 성공 조건

- [x] 이미 수집한 실제 SDLPoP 데모의 연속 12장(번호 40~51)을 해시·번호로 검증하고 점무늬 없는 4명도 입력을 만든다.
- [x] 기존 생명력·중간톤 보정을 유지하며 2bpp 변환·복원·2배 확대·화면 여백을 검증한다.
- [x] 기존 제한 스케치에 빌드 시 선택하는 GAME 12장 재생만 추가한다. 앱 Flash에 저장된 입력을 사용해 USB 전송 병목 없이 측정하며 실시간 게임 플레이와 구분한다.
- [x] 기존 STILL/MOVE 동작과 제한을 보존한다. GAME에는 관찰용 100ms 대기를 넣지 않는다. 파형·드라이버·구동 단계 수를 수정하지 않는다.
- [x] 실제 코드 native/ASan/UBSan, 변환 테스트, ESP32 빌드와 해시를 확인하고 로컬 커밋한다.
- [ ] 필요한 초기 정리·관찰과 시작 예고 뒤 단일 12장만 실행하고 완료/전원OFF/10초 무출력 및 실물 상태를 기록한다.

## 가정 및 제약

- 사각형 시험에서 큰 깜빡임·변형은 없었고 흐릿한 이동 경로 잔상은 남았다. 반복 주사나 임의 파형 강화로 이를 숨기지 않는다.
- 기존 수집 원본은 artifacts에 보존돼 있다. 생성 헤더/미리보기/원본 로그는 제외 경로에 두고 생성 도구·명령·해시를 커밋해 재현 근거를 남긴다.
- 게임 로직·입력·USB 실시간 전송을 연결하지 않는 제한 녹화 재생이다. 원본 수집 간격 약83ms와 실제 완료 간격을 분리한다.
- 실물 준비가 늦어지면 마지막 사용자 관찰 시점과 달라지므로 시작 전에 예고하거나 필요한 관찰 준비만 확인한다.

## 영향 범위

- host/prepare_painter_clip.py, tests/test_painter_clip.py: 4명도 변환과 입력 검증·생성.
- firmware/painter_bounded/painter_bounded.ino, tests/test_painter_bounded.py: 선택적 GAME 경로·확대·횟수·지연 검증.
- .local/artifacts: 기존 백업·빌드 보존, 별도 게임 빌드/헤더/미리보기/실행 기록.
- 문서·계획: 조건, 측정, 사용자 관찰과 다음 단계.

## 실행 계획

- [x] 1. 실제 연속 입력 검증·4명도 생성 → 소스 번호/해시/픽셀·생명력/경계 테스트와 미리보기 확인.
- [x] 2. GAME 제한 경로 → 기존 회귀 + 실제 확대 픽셀·12장/종료/오류·대기 없음 검증.
- [ ] 3. 빌드·커밋·단일 업로드 READY → 공식 코어/정본 드라이버/입력/앱 해시와 백업 대조.
- [ ] 4. 초기 정리 상태·짧은 재생 관찰 → 실제 명도 전이 시간과 가독성·잔상, 종료 후 무출력.

## 위험 및 롤백

드라이버 파형은 그대로지만 실제 게임의 명도 전이가 두 주기를 요구할 수 있다. 12장·30초 앱 제한·45초 호스트 한도를 유지한다. 오류에는 중단하고 자동 반복하지 않는다. 기존 Painter v2와 제조사 앱·출고 백업을 보존한다. 새 기능은 선택적 빌드 경로이며 관련 커밋으로 되돌린다.
