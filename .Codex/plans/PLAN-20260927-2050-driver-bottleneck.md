## 요청 사항

687ms 표시 처리의 대기·행 스캔·구동 단계를 분석하고 근거가 있는 개선 후보를 하나 추린다. 사용자의 개입은 필요한 실물 관찰 시점에만 요청한다.

## 성공 조건

- [x] 현재 S3/IDF4 경로와 RTOS tick·파형·DMA·RMT의 실행 순서를 확인한다.
- [x] 호출 횟수와 명목 시간 예산을 재현 가능한 도구로 계산한다. 병렬 시간과 실제 시간을 혼동하지 않는다.
- [x] SDK 반환 계약과 다른 완료 콜백을 최소 수정하고 실제 함수 추출 테스트에서 수정 전 실패·수정 후 통과를 확인한다.
- [x] 기존 DMA 보호·행 순서 호스트 검증과 ESP32 빌드를 통과한다. 단계 수·파형·전원 순서는 유지한다.
- [x] 성능은 미측정으로 표시하고 후속 단일 비교 시험의 조건·판정·중단을 문서화한다.
- [x] 하위 저장소 수정부터 로컬 커밋하고 상위 참조·문서를 커밋한다. push 없음.

## 가정 및 제약

- 현재 확인된 f1607da 드라이버, ESP32 코어2.0.17·IDF4.4.7·240MHz·tick1ms를 기준으로 한다.
- 소스 분석 중 완료 콜백이 단순 완료 플래그를 설정한 뒤 항상true를 반환하는 것을 발견했다. SDK 계약상 반환값은 태스크를 깨웠는지이며 완료 여부가 아니다. 이 최소 수정은 파형 재설계가 아니므로 Medium으로 진행한다.
- 영구 작업자·RMT 묶음·DMA 재구성·구동 단계 축소는 후보 평가만 한다. 구현 전에 High 권장 여부를 안내한다.
- 이번 단계는 업로드·패널 구동을 하지 않는다. 실물 성능 개선을 선언하지 않는다.

## 위험 및 롤백

불필요한 ISR yield 요청 제거의 실제 시간 효과는 미측정이다. SDK가 큐로 깨운 태스크의 yield 요청은 SDK에서 별도 유지한다. 잘못된 속도 보장을 하지 않는다. 필요하면 하위 최소 수정 커밋과 상위 참조를 되돌리고 기존 빌드 산출물을 사용한다. 장치의 기존 앱은 이번 단계에서 유지한다.

## 실행 기록

- S3 USER_I2S_REG=0, SDK tick1ms, RMT/I80 10MHz,15단계×2극성 확인. 소스 해시를 고정한 예산 도구·6개 테스트 통과.64행 RMT16,380회·LCD1,980회·데이터49.104ms,400행 LCD12,060회·데이터299.088ms. 병렬 시간은 합산하지 않는다.
- 콜백 계약 테스트는 수정 전 assertion 실패(-6), 수정 후 통과. 별도 드라이버 브랜치 codex/eink-pop-lcd-callback에9b8dcdba04ed03ee70dba412667803b1dac1adfd 로컬 커밋.
- 기존 드라이버22개 파이프라인 사례·LUT/실패/DMA 보호와 USB 스케치47개 시나리오 통과. ESP32-S3 빌드 성공, 기존 round 선언 경고는 보존.
- 앱281,840바이트·SHA-256 14e2283dd41b8fcfcb3e35021bc3fd3409e98525f37baf3a553b88f370960c48. 실제 드라이버 의존성·앱 내부 새 식별자 확인. 기존 장치 앱은 유지하며 업로드/패널 접근 없음.
- 계산/빌드 증거 artifacts/driver-budget-20260927 보존. 상세 비용·후보 판정·동일12장 후속 시험 조건을 문서화. 속도 개선은 미측정이며 후속 동기화/RMT/DMA 구현은 High 권장을 사전 안내했다.
