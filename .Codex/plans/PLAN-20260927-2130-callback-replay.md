# 작업: 동일 화면 재생으로 콜백 수정 검증

| 항목 | 내용 |

| 생성일 | 2026-09-27 |
| 상태 | 완료 — 동일12장 실측·사용자 관찰·후속 우선순위 기록 |
| 위험도 | 중간 — 검증된 앱 업로드, 준비 응답 후 최대12장 단일 시험 |

## 요청 사항

이전12장과 동일한 픽셀을 전송해 콜백 수정의 실제 효과를 확인하고, 결과에 따라 다음 구동 최적화의 우선순위를 결정한다. 임의 게임 조작이나 반복 실물 시험은 하지 않는다.

## 성공 조건

- [x] 원본 패킷·CRC·ACK를 검증한 뒤 같은12개 비트맵을 재생하는 도구를 구현한다.
- [x] 기존 전송기의 ACK/CRC/시간 제한/STOP을 재사용하고 송신 전 드라이버 설정을 확인한다. 픽셀 일치와 잘못된 설정·파일·순서의 거부를 테스트한다.
- [x] 백업·대상 USB 장치·빌드 해시 확인 뒤9b8dcdb 앱을 한 번 업로드하고 READY만 확인한다.
- [x] 사용자가 화면 관찰 준비됐다고 답한 뒤에만 최대12장 재생한다. 출력 종료와 추가10초 무갱신을 검증한다.
- [x] 같은 화면별 표시/흰색/검정 처리 시간을 이전과 비교하고 사용자 관찰을 분리해 기록한다. 실제 이득에 따라 후속 후보를 선택한다.
- [x] 관련 변경을 로컬 커밋하고 push하지 않는다.

## 가정 및 제약

- 드라이버9b8dcdb와 검증된 USB v3 앱은 이전 단계에서 빌드 완료. 이번에는 파형·단계 수·DMA 구조를 추가 변경하지 않는다.
- 저장된 비트맵을 검정/흰색 RGB로 풀어 기존 변환기로 다시 확인한다. 원래 RGB 중간톤 입력은 복원하지 않는다. 핵심 비교는 보드의 display/white/black 시간이며 호스트 변환·직렬 간격 전체를 콜백 효과로 오인하지 않는다.
- 모델 학습 표본은 이전 f1607da 결과로 보존한다. 새 측정으로 자동 덮어쓰지 않는다.
- 패널 관찰은 사용자 개입이 필요하다. 그 전까지 도구·테스트·업로드·별도 소스 검토를 진행한다.

## 영향 범위

- host/usb_frame.py: 프레임 읽기 함수 선택 인자만 추가, 기존 기본 동작 유지.
- 추가 host/replay_frames.py, tests/test_replay_frames.py: 검증된 입력 재생과 회귀 검사.
- docs/드라이버-병목-분석.md, docs/개발-인계.md, README.md 및 계획의 결과 기록.
- artifacts/.local: 복원 화면·업로드/재생 원본 로그·한 번 실행 wrapper.

## 실행 계획

- [x] 1. 동일 입력 재생·거부 조건 구현 → 기존 호스트 시험과 신규 PTY/픽셀 검증.
- [x] 2. 단일 업로드와 준비 → 기기·백업·해시·READY 확인, START0회.
- [x] 3. 관찰 준비 응답 후 단일12장 → ACK/CRC/종료/추가10초와 관찰 결과 확인.
- [x] 4. 차이 분석·후속 후보 결정·문서·커밋 → 실제 수치와 가정 구분.

## 위험 및 롤백

실물 손상·장시간 안전성을 보장하지 않는다. 기존 제한과 최초 정리를 유지하고 무한 반복하지 않는다. 오류·재부팅·미종료에는 해당 시험을 중단해 다운로드 모드로 정지한다. 기존 앱·출고 백업은 해시를 확인해 보존한다. 같은 조건에서도 단일 실행의 차이를 통계적 보장으로 해석하지 않는다.

## 실행 기록

- 원본12장 전부 같은 payload·게임 번호 순서로 복원. 신규8개·기존 호스트29개 테스트 통과. 잘못된 대상 설정은 FRAME 없이 STOP하는 PTY 검증 포함.
- 출고 백업·원래 앱·새 앱 해시와 현재 동일 USB 장치 확인 후 업로드1회. Flash4구간 해시·READY 확인, START0회·직렬 포트 닫힘. 현재9b8dcdb 후보 앱이 시작 대기한다.
- 사용자 관찰 준비 질문을 전송했으며 답변 전에는 재생하지 않는다. 실제12장 비교·시각 평가는 아직 남았다. 코드·준비 기록을 먼저 로컬 커밋하고 후속 결과는 별도 커밋한다.

- 사용자 “시작” 승인 후 단일 실행했으나 START 뒤 남은 READY와 빈 CRLF를 파서가 거부했다. START1회·FRAME0회·25바이트 송신, ACCEPT/성능 측정 없음. 오류 정지 명령 성공, 보드는 다운로드 모드다. 원본 실패 기록은 덮어쓰지 않는다.
- 같은 시험의 오류 수정: ACCEPT 전 정확히 빈 줄만 허용하며 기존 마감·로그 상한·재부팅/오류 검사를 보존한다. 정상 시작, 빈 줄만 오는 시간초과, 잘못된 공백/재부팅, ACCEPT 이후 빈 줄 거부를 PTY로 검증한다. 재시험 전 장치는 앱 READY까지 복귀시키고, 화면 관찰이 가능한지 확인한다. 파형·펌웨어 변경 없음.

- 호스트32개·재생8개 테스트 통과. 시작 전 빈 줄 허용만 추가했으며 펌웨어·파형은 변경하지 않았다.
- 기본 RTS 복귀 명령은 READY가 없었다. 내장 USB 초기화 후 READY를 확인했다. Flash 쓰기·START0회. 실패/복귀 기록은 별도 경로에 보존했다.
- 오류 처리로 시간이 지나 사용자에게 다시 관찰 가능한지 요청했다. 새 단일 시도는 별도 로그 경로를 사용하며 기존 기록 존재 시 실행을 거부한다.

- 사용자 “시작해도 됨” 뒤1회 재시험 성공. START1회·동일12장·CRC/ACK/config 통과, 화면 실행12.950704초와 종료 후10.001668초 추가 응답 없음 확인.
- 후속 표시687.038→679.455ms(-1.104%).30~34행 변화 거의 없음,98~102행 약20.806ms 감소. 단일 실행이라 효과를 보장하지 않는다. 기존 모델 보존.
- 사용자: 누락·깨짐 없음, 깜빡임·잔상은 잘 느껴지지 않음, 순간이동 느낌은 여전·움직임이 거의 느껴지지 않음, 마지막 멈춤. 부드러운 움직임 목표 미달성.
- 후속 우선순위: 연속 fast skip RMT 호출 묶음을 오프라인에서 검증. 단계 수·유효 구동 펄스 변경보다 먼저 행 경계·버퍼·완료 순서와 호출 감소를 검증한다. 새 펌웨어 업로드는 포함하지 않는다. 결과·문서를 로컬 커밋하며 push하지 않는다.
