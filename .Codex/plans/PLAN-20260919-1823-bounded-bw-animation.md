- [x] 640×400 영역에 흑백 사각형을 최대 12프레임 출력하고, 종료 후 패널 전원을 끈 채 추가 갱신 없이 유지한다. 전원 끄기 함수 반환·추가 갱신 없음과 실물 멈춤을 확인했으며 전압은 계측하지 않았다. 지연 결함의 한계는 실행 기록 참조.

## 가정 및 제약

- 대상: `Screen-4.7-S3 V2.4 2024-12-03`, Mac의 USB 급전·직렬 연결.
- 재사용: Arduino CLI 1.5.1, 프로젝트 ESP32 코어 2.0.17, 제조사 드라이버 커밋 `50224221fb81a8fcf9068532374b775af84a38d4`. 전역 환경·드라이버 소스·SDLPoP는 변경하지 않는다.
- 표시할 색은 흑백 두 가지지만, 검증된 드라이버의 **4비트 버퍼·회색조 출력 경로**를 사용한다. 1비트 고속 출력 시험이나 게임 성능 결과로 부르지 않는다.
- 제조사 `calc_epd_input_1bpp()`는 `mode`를 사용하지 않아 흰색 지우기 모드로 전환되지 않는다. 1비트 경로의 다른 정렬·행 종료 문제는 실물 영향이 미검증이다. 이번에는 해당 경로·임의 파형·직접 펄스 조정·드라이버 수정을 제외한다.
- 제조사는 장시간 부분 갱신으로 잔상과 복구 불가 손상이 생길 수 있다고 경고한다. 아래 횟수·시간은 시험량 제한이며 안전이 검증된 임계값이 아니다. 특정 정리 주기의 안전성도 보장하지 않는다.
- USB 픽셀 전송, 게임 연동, 추가 입력 장치, Pi·배터리·오디오·케이스는 범위 밖이다.
- 현재 Git은 초기화됐으나 파일은 아직 커밋되지 않은 상태다. 새로 보이는 `.serena/`를 포함한 무관한 파일은 보존한다.

## 구체적인 시험 조건

| 항목 | 설정 |
| --- | --- |
| 패널 | 960×540 |
| 시험 영역 | `Rect_t{160, 70, 640, 400}`, 화면 중앙 |
| 버퍼 | PSRAM 128,000바이트, 행당 320바이트, 4bpp |
| 픽셀값 | 검정 `0`, 흰 바탕 `15`만 사용 |
| 도형 | 영역 내부 64×64 검은 사각형, y=168, x=24+48×프레임 인덱스 |
| 인덱스 | 0~11, 마지막 사각형 오른쪽 끝 x=616으로 영역 내부 |
| 시작 | USB 직렬 연결 최대 5초 대기, 버퍼·설정 검사, 패널 초기화 1회, 전체 지우기 1회 |
| 프레임 | 버퍼 생성 → 전원 켜기 → 기본 `epd_clear_area()` → `epd_draw_image(..., BLACK_ON_WHITE)` → 전원 끄기 → 250ms 대기 |
| 횟수 | 부팅당 최대 12프레임, 자동 반복 없음 |
| 시간 조건 | 최초 화면 갱신부터 30초에 도달하면 다음 프레임을 시작하지 않음 |
| 종료 | 마지막 프레임을 유지하고 패널 전원을 끈 채 대기, 자동 딥슬립·재부팅 없음 |

주의할 구현 조건:

- 640폭 버퍼를 960폭으로 취급하는 기본 `epd_draw_pixel()`·`epd_fill_rect()`를 사용하지 않는다. 행당 320바이트에 맞춰 흰색 초기화와 사각형 행 채우기를 직접 수행한다.
- 픽셀 패킹은 짝수 x가 하위 nibble이다. 모든 사각형 x와 폭은 짝수이므로 검은 구간을 바이트 단위로 채울 수 있다.
- `BLACK_ON_WHITE`는 기존 검은 그림을 지우지 않으므로 매 프레임 영역 지우기를 수행한다. 지우기 횟수·펄스 길이는 제조사 기본값을 유지한다.
- 초기화는 한 번만 한다. 출력 함수가 반환한 후 패널 전원을 끄고 마지막에 버퍼를 해제한다. S3 경로와 맞지 않는 `i2s_deinit()`는 사용하지 않는다.
- 30초 조건은 드라이버가 정상 반환할 때 다음 갱신을 막는 기준이다. 내부 무한 대기가 있는 드라이버를 강제로 중단하는 하드 타임아웃이 아니다. 재부팅·정지 시 아래 중단 절차를 따른다.

## 측정과 관찰

- 펌웨어 로그: 시작 시 버전·영역·색 수·버퍼 크기·프레임 제한·시간 조건을 출력한다.
- 각 프레임: 순번, 도형 위치, 생성 시간, 전원 조작 시간, 지우기 호출 시간, 그리기 호출 시간, 대기를 제외한 처리 시간, 직전 프레임 시작부터의 간격, 누적 경과 시간을 기록한다.
- 종료: 실제 완료 수, 종료 사유, 전체 경과 시간, 지우기·그리기·처리 시간의 최소·평균·최대를 기록한다. 프레임 간격 역수는 소프트웨어 갱신 빈도로만 표기한다.
- Mac: 업로드 직후 직렬 로그를 최대 60초 수집해 정상 종료와 추가 갱신·재부팅 여부를 확인한다. 로그 수집을 끝내면 포트를 닫는다.
- 사용자: 사각형 이동이 구분되는지, 영역 안팎의 깜빡임과 이전 위치의 흔적, 종료 후 멈춤을 관찰한다. 영상이 없는 경우 실제 패널 fps는 수치로 확정하지 않는다.
- 기준 비교: 첫 시험의 전체 지우기 1,355ms·전체 그림 그리기 약 610ms와 조건 차이를 함께 제시한다. 영역 축소 비율만큼 빨라질 것이라고 추정하지 않는다.

## 위험 및 롤백

- 위험: 제한된 시험이라도 잔상·깜빡임이 생길 수 있다. 제조사가 보장하는 무손상 시험 횟수는 확인되지 않았다.
- 중단: 오류·할당 실패면 추가 갱신을 시작하지 않는다. 호스트에서 재부팅 반복 또는 60초 안에 정상 종료가 없음을 확인하면 보드를 다운로드 모드로 정지시키고 원인을 기록한다. USB 제어가 불가능하면 사용자에게 USB 전원 분리를 요청한다.
- 화면 이상만으로 임의 복구 파형이나 반복 지우기 시험을 추가하지 않는다.
- 펌웨어 롤백: 보존한 `.local/build/first_image/`의 정상 시험 펌웨어를 동일 보드 설정으로 다시 업로드한다. 필요 시 `docs/환경-및-검증.md`의 전체 출고 백업 복구 절차를 사용한다. 펌웨어 복원이 패널 잔상·손상의 복구를 보장하지는 않는다.
- 파일 롤백: 이번 새 스케치·새 검증 문서와 README의 이번 변경만 되돌린다. 첫 시험 기록·백업·외부 라이브러리·SDLPoP·무관한 사용자 파일은 보존한다.
