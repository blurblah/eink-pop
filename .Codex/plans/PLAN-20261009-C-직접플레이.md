## 요청 사항

채택한 C로 다시 직접 플레이한다. 사용자는 직접 조작을 선택했다. 기본 톤·원래 NORMAL 직접 주사표·2ms·방/컷신 전환 정리를 유지한다.

## 성공 조건

- [x] 기존 C 앱·게임·호스트 해시와 동일 장치/복구 백업 확인.
- [x] 새 실행 경로에서 업로드/READY 후 사용자 시작 확인.
- [ ] 게임 준비 직후 보드 표시, STOP/최대600초6000장/30초 주기 정리 유지.
- [ ] 종료 시 전송/정리 근거·게임 종료·사용자 관찰을 기록.

## 가정 및 제약

새 파형·전압·톤 변경 없음. 잔여90%,55%미만 중단. 현재 다리 잔상/벽면 선은 해결된 것으로 처리하지 않는다. 기존 결과를 덮어쓰지 않는다. 사용자가 만든 다른 게임 프로세스를 종료하지 않는다.

## 영향 범위

44회 로컬 실행/분석 도구와 기록. 기존 게임 컨트롤러의 PPM 판독에 컷신 메타데이터를 반영하고, 분석은 제한된 동일 입력 유지 프레임을 별도로 집계한다. 생산 게임/호스트/펌웨어 코드는 변경하지 않는다.

## 단계별 작업과 검증

- [x] 기존40회 실행 도구를 새 경로와 C 설정에 맞춤 → 구문/실제PPM/분석데이터 계약 점검.
- [x] 기존43회 앱 재사용 업로드 → 해시4영역/READY8초/START0 확인.
- [x] 사용자 시작 응답 후 직접 플레이 → 실제 ACK와 진행 상태 확인.
- [ ] STOP/상한/오류 종료 → OFF/10초 무출력과 자체 게임 종료, 필요 시 제조사 정리.

## 위험 및 롤백

사용자 STOP은 마지막 화면/OFF를 보존하여 관찰 후 정리한다. 상한/오류는 자동 제조사 정리까지 수행한다. 정상 로딩의 새 입력 공백은 기존10초 상한을 유지한다. 종료/오류 결과와 정리 결과를 확인해 중복 실행하지 않는다. push하지 않는다.
