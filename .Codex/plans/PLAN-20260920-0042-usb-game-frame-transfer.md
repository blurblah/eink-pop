## 요청 사항

> Mac에서 실행되는 SDLPoP 화면을 USB로 보낸다. 게임 화면 한 장을 먼저 확인하고 이후 제한 연속 시험을 진행한다. 관련 변경은 작업 브랜치에 로컬 커밋하고 push하지 않는다.

직전 설명에서 Mac의 게임 실행·입력·오디오, ESP32의 화면 출력, 기존 두 호출 차분 방식, 정지 화면 후 제한 연속 시험을 제안했고 사용자가 “진행해”라고 승인했다. 구현·검증·업로드는 이 범위에서 진행한다. 실제 패널 출력은 사용자 관찰 준비 답변 후에만 시작한다.

## 성공 조건

- [x] SDLPoP의 선택적 최신 화면 추출이 USB·패널 대기나 파일 쓰기로 게임 렌더링을 막지 않는다.
- [x] 320×200 화면을 1bpp 8,000바이트로 보내고, ESP32에서 중앙 640×400으로 확대한다. (호스트·네이티브 모의 검증, 실물은 아래 별도 조건)
- [x] CRC·길이·순서·세션을 검사하며 한 프레임만 진행한다. 잘못된 첫 프레임은 패널에 접근하지 않는다.
- [x] 최초 전체 지우기 한 번, 이후 바뀐 픽셀만 흰색→검정으로 갱신한다. 변경 없는 프레임은 패널을 구동하지 않는다.
- [x] 부팅만으로 출력하지 않으며 세션당 최대 1~12프레임·30초 새 갱신 시작 제한, 오류 시 재전송·재시작 없음이 검증된다.
- [x] 실제 소스 하네스·호스트 직렬 모의 시험·게임 빌드·펌웨어 빌드를 통과한다.
- [ ] 준비 답변 후 게임 화면 한 장을 실제 출력하고 사용자 관찰을 기록한다. 연속 시험은 정지 화면 확인 뒤 별도 준비를 받아 진행한다.
- [ ] 변경·검증 기록을 로컬 커밋하며 기존 원본·백업을 보존하고 push하지 않는다.

## 가정 및 제약

- 표시: 320×200 RGB를 고정 휘도 문턱값으로 흑백 변환, 1=검정·MSB 우선. 패널 x=160,y=70, 2×2 정수 확대. 디더링·4:3 비율 보정은 이번 범위 밖이다.
- SDLPoP 작업 브랜치의 기존 `<strings.h>` 변경은 유지한다. 외부 원본은 읽기 검증만 한다.
- 드라이버는 `f1607da`의 기존 `epd_draw_image()`를 사용한다. 교차 API·파형·시간표는 변경하지 않는다.
- 최신 슬롯과 작업 스레드가 PPM을 원자 교체한다. 메인 스레드는 잠금이 즉시 가능할 때만 복사하고, 호스트는 ACK 뒤 최신 파일을 읽는다. USB 출력 지연에 맞춰 게임 시간을 늦추지 않는다.
- 실제 화면 변화·잔상·입력 지연은 사용자 관찰과 구분해 기록한다. ACK는 드라이버 호출·전원 끄기 반환을 뜻하며 광학 측정이 아니다.
- 현재 제공된 스킬 중 이 작업에 직접 적용되는 스킬은 없다. 기존 프로젝트 문서·테스트에 절차를 남긴다.

## 위험 및 롤백

게임 색상을 단순 흑백으로 바꿔 세부 요소가 사라질 수 있다. 실물 확인 후 별도 개선 여부를 판단한다. 기존 부분 갱신의 잔상·중간 모양도 남을 수 있으며 장시간 사용 안전성을 보장하지 않는다. 프레임 오류·시간초과·재부팅에서 자동 재시도하지 않는다. 진행 중 드라이버 호출은 강제로 끊지 않으므로 30초는 새 갱신 시작 제한이다.

출고 백업과 `bw_delta`, `bw_interleaved` 바이너리는 덮어쓰지 않는다. 롤백은 새 작업 브랜치·상위 참조와 명시적으로 선택한 이전 앱에 한정하며 실제 복귀를 수행했을 때만 기록한다.

## 실행 기록

읽기 조사에서 SDLPoP의 최종 320×200 RGB24 합성 지점, SDL 비차단 잠금·작업 스레드, ESP32 코어 2.0.17 HWCDC의 기본 256바이트 수신 큐를 확인했다. 새 펌웨어는 시작 전에 수신 큐를 8,192바이트로 확보하고 호스트는 한 프레임만 보낸다. 게임 루프에서 직접 파일 쓰기를 하지 않는다.

출고 백업·직전 두 앱의 크기·SHA와 원본 두 저장소 상태가 기존 기록과 같았다. 게임 추출 하네스 13개, 실제 USB 스케치의 ASan/UBSan 검증 40개, 호스트 PTY 시험 24개를 통과했다. 독립 리뷰에서 START 전 잔여 READY 분할 수신과 DONE 뒤 추가 STATS 처리 문제를 고쳤고 화면 구동 직전 시간 제한도 재확인한다. 실제 게임 4초 실행에서 sequence 10→22→34→46의 최신 PPM과 정상 종료·임시 파일 정리를 확인했다. 자동 스크린샷은 표시 훅 전에 종료하므로 첫 실물 입력은 연속 추출로 얻은 유효한 1레벨 PPM 한 장을 사용한다.

SDLPoP는 `53b2ff3`으로 로컬 커밋했다. 최종 펌웨어 빌드가 성공했고 앱 281,600바이트의 SHA는 `dfc935d48f86e67f66fc57136c6a15ffb7cce97109cc95447b514f7b274d74a0`이다. 빌드/검증 스케치 SHA가 일치하고 22개 드라이버 컴파일 단위가 새 저장소 경로임을 확인했다. 실제 보드 게임 출력은 아직 시작하지 않았다.

상위 구현은 `207ed1e`로 커밋한 뒤 01:01:48~01:02:01 KST에 동일 보드에 업로드했다. 백업·직전 앱·새 빌드 해시를 대조했고 Flash 네 구간 쓰기 해시 검증이 통과했다. 다시 조회한 같은 장치에서 5.133초 수신만 해 READY/panel=untouched 8줄을 확인하고 01:02:07에 포트를 닫았다. START는 0회다. 첫 한 장 시험의 관찰 준비 답변을 기다리며 자동 시작하지 않는다.
