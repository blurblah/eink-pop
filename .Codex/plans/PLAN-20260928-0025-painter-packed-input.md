# 작업: NORMAL 화질을 유지하는 2bpp 직접 입력 비교

| 항목 | 내용 |
| --- | --- |
| 상태 | 실행 중 — 사용자 연속 진행 승인 범위 |
| 위험도 | 중간 — 기존 API와 같은 파형의 제한 비교 |

## 요청 사항

NORMAL은 잔상·명암이 개선됐으나 느리다. 파형·구동 시간을 보존하며 중복 프레임 변환 비용을 줄인다. 사용자가 밝기 조정은 추후 가능하다고 했으므로 이 비교의 밝기·입력은 바꾸지 않는다.

## 성공 조건

- [x] 기존 paint와 paintPacked의 목적 버퍼·시작 상태 계약을 확인한다.
- [x] 선택적 PACKED 빌드에서 2bpp 확대·여백·도형을 전 픽셀 대조하고 시작·오류·종료 회귀를 통과한다.
- [x] ESP32 빌드·동일 원본 클립·앱 해시 및 로컬 커밋을 확인한다.
- [x] 제조사 초기 정리 한 번, READY, 15초 예고 후 12장 한 번, DONE/OFF/10초 무출력을 확인한다.
- [ ] 이전 NORMAL과 시간·메모리·관찰 한계를 기록하고 커밋한다. push하지 않는다.

## 가정 및 제약

드라이버7544e2d·H716 NORMAL 직접 전이·파형·핀·전압·주사 대기는 유지한다. 버퍼 준비와 제출 방식만 변경한다. 24ms의 프레임 간 부가 비용은 준비·로그·스케줄링 혼합값이며 제거 가능한 시간으로 단정하지 않는다. 이동 중 하얗게 보이는 현상은 명도와 구동 중간 상태를 분리 측정하지 않았다.

## 영향 범위

- firmware/painter_bounded/painter_bounded.ino: 선택적 packed 버퍼·확대·기존 API 호출·READY 식별.
- tests/test_painter_bounded.py: 2bpp 전 픽셀·경계·안전 계약 검증.
- 문서·계획, .local/artifacts의 별도 빌드·원본 로그.
- 드라이버 submodule: 읽기만 한다.

## 실행 계획

- [x] 1. 중복 변환과 API 계약 확인 → 같은 목표2bpp를 입력하도록 설계.
- [x] 2. 구현·전 픽셀 검증·실기 빌드 → 기존 모드 회귀 및 원본 클립 일치.
- [x] 3. 제한 실측 → 동일 NORMAL v6와 후속 완료 시간 비교.
- [ ] 4. 결과 기록·로컬 커밋 → 속도 및 품질 판단 분리.

## 위험 및 롤백

2bpp의 비트 순서·좌표 오류는 전 픽셀 native 검증으로 잡는다. 부팅당1회·12장·앱30초/호스트45초·OFF를 유지한다. 오류 시 자동 반복 없이 다운로드 정지. NORMAL v6·FAST·제조사 앱·출고 백업 보존.
