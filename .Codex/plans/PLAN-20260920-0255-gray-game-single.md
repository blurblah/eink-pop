## 요청 사항

> 사용자가 확인한 점무늬 없는16계조 게임 미리보기를 같은 보드에 그대로 표시한다.

직전 답변에서 같은 게임 화면을 실제16계조로 한 장 표시하자고 제안했고 사용자가 예시를 확인한 뒤 직접 업로드·표시를 지시했다. 이 승인에 따라 구현·업로드·한 장 출력을 진행한다. 별도 점무늬 계획의 적용이나 회색 연속 전송을 승인한 것으로 확대하지 않는다.

- [ ] 사용자 실물 관찰을 기록하고 관련 변경을 로컬 커밋한다. push하지 않는다.

## 가정 및 제약

- 원본PPM SHA `322cf921b76b6447d227a5cdc27bdedf78f51abef8c3a0d757d2d72c26eb385e`, 미리보기 `artifacts/usb-game-gray16-preview.png`.

- 이번에는32,000바이트 정지 이미지를 새 스케치에 포함한다. USB v1 호스트·펌웨어와 게임 추출 코드는 보존한다. 실시간 회색 게임 전송은 범위 밖이다.
- 드라이버 `f1607dab2df95295e6b50fc0e44c4c092a13938f`, 기존 `epd_draw_grayscale_image()`와 지우기·파형을 사용한다.
- 패딩 영향을 피하려고 전체960폭×400행192,000바이트 버퍼의 좌우를 흰색으로 두고 회색 그림을 삽입한다.
- 사용자의 명시적 표시 요청에 따라 한 번 출력한다. 준비 중 사용자 중단·보류 요청이 있으면 시작하지 않는다.

## 위험 및 롤백

Mac 미리보기와 실제 패널의 밝기·대비가 다를 수 있다. 처음 전체 화면이 깜빡이며 출력한다. 회색조 한 장의 처리 시간은 연속 게임 속도가 아니다. 드라이버 호출은 내부에서 대기할 수 있어 호스트 제한시간으로 강제 중단되지 않는다. 오류 시 재시험하지 않고 기존 다운로드 모드 중단 절차를 사용한다.

출고백업과 직전 USB 앱은 보존한다. 필요하면 검증한 USB 앱으로 복귀할 수 있으며 실제 복귀했을 때만 기록한다. 이번 표시 직후 자동 복귀 업로드는 하지 않는다.

## 실행 기록

제공된 스킬 목록에 직접 맞는 임베디드 정지 화면 스킬은 없으며 기존 저장소 절차를 사용한다. 착수 시 상위 Git 변경 없음과 현재 USB·드라이버 구현을 확인했다.

미리보기의256,000픽셀과 정지 이미지 확대 결과가 일치했다. 실제 스케치11개 검증과 독립 읽기 리뷰를 통과했다. 앱311,888바이트 SHA `08931ac61c28249bed1d23ed07aaa1165abdf1b87a948be54d9e502d5e199648`, 프로그램311,521바이트·전역19,440바이트다. 빌드생성 코드·헤더를 정본과 대조했고 기존 `round` 선언 경고 외 새 경고는 없다. 출고 백업·직전USB 앱 해시도 확인했다. 실제 업로드·표시는 다음 단계다.

구현을 `da12aa3`으로 커밋한 뒤 동일 보드에 업로드해4구간 Flash 해시와 READY9줄을 확인했다. 사용자의 한 장 표시 지시에 따라03:06:31.789 KST에RUN을1회 전송했다.199표본 선행 검사 통과 후 전체 지우기1,360.884ms·회색조 그리기534.942ms, 패널 처리 합1,896.654ms로 정상 종료했다. DONE 뒤10.090864초 추가 응답 없이03:07:03.897에 포트를 닫았다. 원본 로그의 시간 합·표본·횟수·이미지 식별을 재검산했다. 사용자에게 미리보기와 가독성 비교를 요청했으며 답변 대기다. 자동 재출력·복귀 업로드는 하지 않았다.
