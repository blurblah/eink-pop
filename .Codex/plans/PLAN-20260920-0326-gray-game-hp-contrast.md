## 요청 사항

> 실제16계조 게임 화면은 생명력 화살표를 제외하면 훌륭하다. 해당 두 빨간색만 밝은 회색·흰색으로 보정해 보드에 표시한다.

생명력 보정판 업로드 뒤 아직RUN을 보내기 전에 사용자가 “전반적으로 좀 어두운 느낌인데 밝게도 가능한가?”, 이어 “약간만 더 밝아지면 좋을 것 같기는 함”이라고 요청했다. 이를 반영해 생명력의15/12 보정을 유지하고 그 외 중간 회색1~13만 한 단계 밝힌다. 검정0·밝은14·흰색15는 유지한다. 최종 한 장만 표시하며 생명력 보정판은 별도출력하지 않는다.

직전 제안과 사용자 승인이 있어 추가 구현 승인을 요청하지 않는다. 단일 출력과 종료 관찰은 기존 한 장 시험을 따른다.

## 가정 및 제약

- 현재 표시 장면·확대·그리기·파형·명령 제한은 유지한다. 헤더의32,000바이트 이미지와식별SHA만 변경한다.
- 점무늬·회색 연속 전송·게임 로직 변경은 포함하지 않는다. 중간회색 밝기는 후속 사용자 요청에 따라 한 단계만 올린다.
- 이번 이미지는 생명력3칸이 채워진 정지 장면이다. 빈 칸과 깜빡임의 게임동작 실물 검증까지 완료했다고 기록하지 않는다.
- 제공 스킬 목록에 직접 맞는 임베디드 이미지 검증 스킬은 없으며 기존 코드·검증 절차를 사용한다.

## 위험 및 롤백

밝기 개선의 실물 정도는 확인 전이며 기존 회색조 파형을 유지한다. 오류 시 재전송·반복출력 없이 기존 중단 절차를 사용한다. 이전32,000바이트 이미지와 앱은 Git 및 별도빌드 디렉터리에 보존하고, 필요하면 이전앱을 업로드해 복귀한다. 자동복귀·push는 하지 않는다.

## 실행 기록

착수 시 변경 없는 Git 상태와 기존 한 장 출력·생명력색 분석 기록을 확인했다.

독립 대조에서54픽셀만 변경·나머지보존을 확인했다. 데이터SHA는 `4e7d57a3aa59686d9cd5b294ed51198a6bd4987804b9463c1b6766b46a786417`이다. 기존11개ASan/UBSan검증과 Arduino 빌드가 통과했다. 스케치SHA는 이전과 같은 `9131cf6da08c23fb79b6644f84cd5977c5b37205848e23134e2a98addebc6f33`, 헤더SHA는 `6dd682cdea6a5f11891c079cee33ee6c144930984b0e827e185432613a2477ca`이며빌드·테스트와 일치한다. 앱311,888바이트SHA `de9b6eca1e55011cc53d08069d85233f4b5eaa3bcf32e1454246967fd4f473b1`를 새빌드 디렉터리에 보존했다. 기존백업·앱은 크기와해시를 다시 확인했다.
