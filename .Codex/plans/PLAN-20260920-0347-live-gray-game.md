## 요청 사항

정지 화면에서 확인한 밝기·생명력 보정을 실행 중 SDLPoP 프레임에 적용하고 Mac 키보드로 최대 12장 게임 연동을 시험한다. 직전 설명에 대한 사용자 “진행”을 이 범위의 승인으로 기록한다. 모든 변경은 로컬 커밋, push 없음.

## 성공 조건

- [x] 최신 RGB 프레임의 4bpp 변환이 확인된 정지 이미지와 일치한다.
- [x] 버전·길이·CRC·순서·시간 제한과 2배 확대를 호스트/펌웨어 테스트로 검증한다.
- [x] 새 ESP32-S3 바이너리를 빌드·검증·업로드하고 화면을 건드리지 않는 READY를 확인한다.
- [ ] 사용자가 준비된 시점에 실제 게임 입력·화면 변화를 최대 12장 시험하고 종료·관찰 결과를 기록한다.

## 가정 및 제약

- Mac의 기존 RGB PPM 추출기를 재사용한다. 기본 게임 팔레트와 생명력 위치가 대상이다.
- 기본 밝기는 중간 회색 1~13을 한 단계 밝게 한다. 생명력 영역 x<69, 194≤y<199의 RGB(228,0,0)/(184,0,0)는 각각 15/12로 우선 변환한다.
- 프로토콜 v2: 320×200, 4bpp, 짝수 x 하위 nibble, 32000바이트. ACK는 clear_us/draw_us로 측정한다. 이전 v1과 혼용하지 않는다.
- 제조사 grayscale API는 흰 바탕을 전제한다. 변경 프레임마다 검증된 전체 지우기 후 회색 출력, 무변경은 전원 구동을 생략한다. 새 파형·영역 지우기 최적화는 포함하지 않는다.
- 최초 패널 구동부터 30초 이후 새 갱신 금지, 최대 12장, RX 5초, 최초 약 20초 지연 검사와 종료 후 10초 확인을 유지한다. 시작한 갱신은 전원 끄기까지 완료한다.
- 이전 실측은 전체 지우기+회색 한 장 약 1.9초다. 이번 시험은 연동과 실제 지연 평가이며 부드러운 플레이를 보장하지 않는다.
- 보드 표시 시험은 사용자의 관찰 준비 응답 후 시작한다. 업로드까지는 진행 승인 범위다.

## 위험 및 롤백

- 위험: 각 변경 프레임의 전체 지우기에 큰 깜빡임과 지연이 예상된다. 갱신 중 게임 로직은 계속 진행하여 중간 동작을 건너뛴다. 광학 완료와 장기간 안전성은 로그로 보장할 수 없다.
- 롤백: 이전 정지 16계조와 USB v1 바이너리를 별도 빌드 경로에 보존한다. 현재 출고 16MB 백업도 보존한다. 이번 호스트/펌웨어는 함께 v2로 사용한다.

## 실행 기록

- 드라이버 검토: epd_clear_area는 하단 행 펄스가 전체 지우기와 달라질 수 있어 이번에는 기존 epd_clear()를 유지한다. 드라이버 변경은 하지 않는다.
- 실제 source46 PPM 변환이 승인된 정지 이미지 32,000바이트 전체와 일치했다. 호스트 27개와 실제 스케치를 포함한 펌웨어 40개 ASan/UBSan 검증을 통과했다.
- ESP32-S3 빌드 통과. 앱 281,408바이트 SHA a32980619aee342a4808bdedd20ceb93abe990402ba5079b7fa38025e95d1b6e. 스케치·생성 빌드 일치 및 드라이버 22개 컴파일 단위 확인. 업로드 전이다.
- 구현·검증을 a56b3b8로 로컬 커밋한 뒤 03:58:56~03:59:17 KST에 같은 보드에 업로드했다. 백업·이전 앱·새 앱 대조와 네 Flash 구간 해시 검증 통과. READY v2 9줄·6.042초 수신만 확인, START 0회·포트 닫음.
- 실제 Mac 게임을 시작해 source12의 1레벨 이미지와 최신 추출을 확인하고 이 프로세스만 임시 정지했다. 사용자 관찰 준비를 요청했으며 아직 12장 전송은 시작하지 않았다. 준비 후 재개하고 시험 뒤 해당 게임 프로세스를 종료한다.
- 사용자 “지금 시작” 뒤 04:03:46 KST에 실제 게임을 재개하고 START 1회·FRAME 1회를 보냈다. source260, CRC·길이·ACK 일치, 보드 처리 1.912초였으나 호스트 ACK는 송신 시작 7.039초 뒤 RX 시간초과 응답과 함께 도착했다. 12장 시험은 실패했다. 오류 종료·다운로드 모드 중단과 게임 정상 종료를 확인했고 자동 재실행하지 않았다.
- 원인은 아직 확정되지 않았다. 코어 HWCDC에서 연결 판정·TX 큐가 지연될 수 있는 경로를 확인했다. ACK 직전에 연결 상태를 최대 100ms 확인하고 연결됐을 때만 출력·flush해 송신 큐 처리를 명시한다. 단순 flush는 연결 끊김 판정 시 큐를 버리므로 무조건 호출하지 않는다. 기존 화면·프로토콜·제한을 유지하는 범위의 통신 보완이며 native 회귀 검증·빌드·업로드 후 사용자 관찰 시험으로 확인한다.
- 사용자 전환 시간을 반영해 다음에는 60초 준비 시간을 별도로 둔다. 실제 게임·패널 시험 시간과 분리하며 키 입력이 이번 RX 시간초과 원인이 아님을 안내했다.
