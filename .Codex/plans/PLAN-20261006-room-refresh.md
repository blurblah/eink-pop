## 요청 사항

방 전환 후 정리 주기를 기다리는 동안 명암이 달라지는 문제를 줄이기 위해 새 방 표시 전에 한 번 정리한다.

## 성공 조건

- [x] 게임 RGB와 레벨/방 번호를 같은 최신 슬롯·원자적 파일로 전달한다.
- [x] 방 전환 중간 검정 화면을 새 방으로 보내지 않는다.
- [x] v9에서 CRC로 보호한 정리 요청과 해당 화면을 묶고, 패치 복원 후 한 번 정리한다.
- [x] 최초/방/주기 정리를 중복 수행하지 않고, 정리 후 기준 버퍼를 동기화한다.
- [x] v7/v8 유지, 오류·STOP·시간·프레임 상한 검증, 로컬 빌드와 기록·커밋.
- [ ] 실물 최종 검증은 사용자 관찰로 별도 판정한다.

## 가정 및 제약

- 정상 게임 플레이의 실제 그린 방 번호를 사용한다. 화면 변화량 기반 추정 없음.
- 광학 일관성의 우회책이며 파형 자체 개선 아님. 방 전환 시 깜빡임/지연 비용을 기록한다.
- 기존 shadow_v1·13주사2ms·600초6000장/STOP·주기30초 유지. 잔여55% 미만 중단, 시작59%.
- 게임 원본 보존, 각 기존 브랜치 로컬커밋, push 없음.

## 영향 범위

- SDLPoP: 선택적 장면 메타데이터·중간화면 제외 및 exporter 동기화 검증.
- host/painter_usb.py, firmware/painter_usb: 명시적 v9 방 정리 요청/응답과 기존 경로 유지.
- 관련 호스트/실제 스케치 검증, 프로토콜·반복 기록.

## 실행 계획

- [x] 1. 게임 렌더/원자 출력, 호스트 메타데이터 읽기 구현 → 실제 SDL 스레드 동기화 검증.
- [x] 2. v9 프레임 정리 비트와 원인 구분 → CRC/패치/정리겹침/순서/STOP 경계 검증.
- [x] 3. 기존 회귀·게임/ESP32 빌드 → 새 산출물 해시, 한도 재조회.
- [x] 4. 준비된 후보와 실물 검증 상태 기록, 하위→상위 로컬 커밋.

## 위험 및 롤백

방 전환 지연/깜빡임 증가. 메타데이터 없는 기존 exporter/v7/v8과 이전 펌웨어 보존. 오류 시 제조사 정리/OFF 복구.
