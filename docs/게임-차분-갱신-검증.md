# 실제 게임 흑백 차분 갱신

2026-09-27, [실행 계획](../.Codex/plans/PLAN-20260927-1827-live-game-delta.md).

## 다른 게임 보드에서도 의미가 있는 이유

게임 실행과 패널 구동은 서로 다른 단계다. 앞선 Mac→USB→ESP32 시험에서 전체 화면 처리 평균 1.911389초 중 전체 지우기에 1.361585초가 들었다. 사용자는 매번 검정으로 전환되는 큰 깜빡임 때문에 이동을 인식하지 못했다. 게임을 다른 보드에서 실행해도 같은 패널·ESP32 출력 경로를 유지하면 이 동작은 남는다.

이번 변경은 프레임 공급원과 무관한 화면 표시 방법을 검증한다. Mac은 현재 실제 게임 프레임을 공급하는 시험 장치다. 나중에 다른 게임 보드가 같은 320×200 흑백 비트맵과 프로토콜을 공급하면 ESP32 표시 코드를 재사용할 수 있다. 새로운 보드의 게임·입력·전송 성능은 별도 검증 대상이다. 패널이나 컨트롤러까지 바꾸면 현재 파형과 측정값을 그대로 적용할 수 없다.

## 구현

- 이전 v1의 두 패스 차분 마스크를 재사용했다. 최초 전체 지우기 후 검정→흰색, 흰색→검정 픽셀만 순서대로 구동한다. 무변경 프레임은 전원도 켜지 않는다.
- 회색 출력 API는 흰 바탕을 전제하므로 단순히 지우기만 제거하지 않았다. 실제16계조 대신 화면 좌표에 고정한 4×4 점무늬로 명암을 표현한다. 기존 중간톤·생명력 보정을 적용한 뒤 흑백으로 변환한다.
- USB v3는 8,000바이트, MSB 우선, 1=검정이다. v1/v2를 거부한다. 현재 수신 제한과 ACK 연결 확인·flush 보호를 유지했다. [프로토콜](USB-화면-프로토콜.md)에 전송·변환 계약을 기록했다.
- 640×400 표시, 최초20초 지연 검사, 최대12장·새 화면 시작30초 제한을 유지했다. 종료 시 패널 구동 전원을 끄고 마지막 이미지를 유지한다. 자동 종료 정리나 무한 반복은 추가하지 않았다.
- `repos/LilyGo-EPD47`의 `f1607da`, `repos/SDLPoP`의 `53b2ff3`를 그대로 사용한다. 게임 실행·추출기·패널 파형 변경은 없다.

## 남은 확인

실제 게임에서 큰 깜빡임 감소, 인물 이동 식별, 점무늬 가독성, 잔상과 처리 시간을 확인해야 한다. 기존 사각형 차분 시험의 후속 처리 약0.682초·간격0.932초는 게임 성능을 보장하지 않는다. 일반 흑백 호출도 기존15단계 파형을 사용한다. 두 패스 사이 일부가 분리돼 보이거나 점무늬가 거칠어질 수 있다.

사용자가 관찰 준비를 알린 뒤 게임 창으로 전환할60초와 지연 검사 시간을 제공하고 최대12장으로 비교한다. 아직 이번 버전의 실물 화면 시험은 시작하지 않았다. 장시간 부분 갱신의 안전성과 플레이 가능성은 이번 자동 검증만으로 판정하지 않는다.
