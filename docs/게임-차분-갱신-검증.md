# 실제 게임 흑백 차분 갱신

2026-09-27, [실행 계획](../.Codex/plans/PLAN-20260927-1827-live-game-delta.md).

## 다른 게임 보드에서도 의미가 있는 이유

게임 실행과 패널 구동은 서로 다른 단계다. 앞선 Mac→USB→ESP32 시험에서 전체 화면 처리 평균 1.911389초 중 전체 지우기에 1.361585초가 들었다. 사용자는 매번 검정으로 전환되는 큰 깜빡임 때문에 이동을 인식하지 못했다. 게임을 다른 보드에서 실행해도 같은 패널·ESP32 출력 경로를 유지하면 이 동작은 남는다.

이번 변경은 프레임 공급원과 무관한 화면 표시 방법을 검증한다. Mac은 현재 실제 게임 프레임을 공급하는 시험 장치다. 나중에 다른 게임 보드가 같은 320×200 흑백 비트맵과 프로토콜을 공급하면 ESP32 표시 코드를 재사용할 수 있다. 새로운 보드의 게임·입력·전송 성능은 별도 검증 대상이다. 패널이나 컨트롤러까지 바꾸면 현재 파형과 측정값을 그대로 적용할 수 없다.

## 구현

- 이전 v1의 두 패스 차분 마스크를 재사용했다. 최초 전체 지우기 후 검정→흰색, 흰색→검정 픽셀만 순서대로 구동한다. 무변경 프레임은 전원도 켜지 않는다.
- 회색 출력 API는 흰 바탕을 전제하므로 단순히 지우기만 제거하지 않았다. 실제16계조 대신 화면 좌표에 고정한 4×4 점무늬로 명암을 표현한다. 기존 중간톤·생명력 보정을 적용한 뒤 흑백으로 변환한다.
- USB v3는 8,000바이트, MSB 우선, 1=검정이다. v1/v2를 거부한다. 현재 수신 제한과 ACK 연결 확인·flush 보호를 유지했다. [프로토콜](USB-화면-프로토콜.md)에 전송·변환 계약을 기록했다.
- 640×400 표시, 최초20초 지연 검사, 최대12장·새 화면 시작30초 제한을 유지했다. 종료 시 패널 구동 전원을 끄고 마지막 이미지를 유지한다. 자동 종료 정리나 무한 반복은 추가하지 않았다.
- `repos/LilyGo-EPD47`의 `f1607da`, `repos/SDLPoP`의 `53b2ff3`를 그대로 사용한다. 게임 실행·추출기·패널 파형 변경은 없다.

- 미리보기는 제외된 `artifacts/usb-game-delta-v3-20260927.pgm/.png`에 보존했다. 전송 데이터의 픽셀을 2배 nearest 확대했으며 이미지 생성 모델이나 별도 그림 보정을 사용하지 않았다.

## 실제 게임 12장 시험

사용자 “오케이 진행” 후 SDLPoP를 실행해 새 source12 프레임을 확인하고 임시 정지했다. 창 전환 시간60.007928초를 제공한 뒤18:41:00 KST에 게임을 재개했다. 장치 포트는 실행 직전 재식별했다. 지연 검사20.098306초·199표본(sign0=110,sign1=89)을 통과하고 단 한 번의 START로 서로 다른12장을 모두 적용했다.

송신 비트맵을 독립 해석해 ACK의 각 극성 호출 여부와 대조했다. 후속 변화 픽셀은 원본 기준18~498개였고, 바뀐 행 범위에 따라 호출 시간이 달라졌다. 첫 화면만 전체 지우기를 실행한 것이 로그로 확인됐다. 이전16계조의 후속 간격 평균2.328909초보다 이번 호출 간격은 짧다. 그러나 서로 다른 사용자 조작·장면의 짧은 시험이며 광학 완료·입력 지연·실제 패널fps를 뜻하지 않는다.

시험 원본은 제외된 `artifacts/logs/usb-delta-v3-20260927-play-*`, 독립 검증은 `-verification.json`, 게임 상태·추출은 `artifacts/usb-game-delta-v3-20260927/`에 보존했다. 장치는 추가 갱신 없이 마지막 이미지를 유지하며 패널 구동 전원은 꺼진 상태로 종료했다. 이 시험이 만든 게임도 정상 종료했다. 다른 시험을 자동으로 이어서 실행하지 않았다.

## 사용자 관찰과 판정

사용자 응답:

> 위치 변화는 이전보다 나았는데 그래도 끊겨서 순간이동 하는 것처럼 보임.
> 그리고 깜빡임도 있었던 것 같다.
> 근데 전반적으로 화면이 왜 도트로 바뀐거지?

위치 변화 식별은 일부 개선됐지만 평균 약1초의 갱신 간격으로 중간 동작을 건너뛴다. 부드러운 게임 움직임을 달성하지 못했다. 후속 전체 지우기0회는 로그로 확인했으나 사용자는 깜빡임이 있었던 것으로 기억한다. 실제 깜빡인 영역·형태는 이 응답만으로 확정할 수 없다. 일반 흑백 호출도 기존15단계 파형과 두 극성 출력을 사용한다.

도트는 이번 호스트 변환에서 실제16계조를 고정 흑백 점무늬로 바꾼 결과다. 원본 게임 그래픽은 그대로다. 기존 회색 출력의 흰 바탕 전제와 검증된 이진 차분을 재사용하기 위한 화질 타협이며, 최종 제품 화질로 결정한 것이 아니다. 사용자의 질문에 이 선택과 한계를 설명했다.

이동 경로의 잔상 정도와 생명력 화살표 가독성은 이번 응답에 없어 미확인으로 남긴다. 점무늬 화질의 수용 여부도 승인받았다고 해석하지 않는다. 현재 결론은 전송·차분 실행 성공과 이동 식별 일부 개선이며 플레이 적합성 개선 성공은 아니다. 장시간 부분 갱신 안전성은 이번 짧은 시험만으로 판정하지 않는다. 추가 패널 시험이나 파형 변경은 실행하지 않았다.
