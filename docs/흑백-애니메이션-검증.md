## 현재 판정

제한된 1회 시험과 관찰 기록을 완료했습니다. 12프레임이 24.077232초에 종료됐고, 종료 후 약 37.3초 동안 추가 갱신·재시작 로그가 없었습니다. 사용자는 오른쪽 이동을 구분했고, 큰 영역의 심한 깜빡임을 관찰했습니다. 이후 오른쪽에 멈췄으며 깜빡임·잔상은 없다고 확인했습니다.

## 빌드·업로드·복귀

프로젝트 루트에서 실행하며 포트는 매번 현재 장치를 조회해 지정합니다. 기존 첫 시험의 바이너리와 로그는 덮어쓰지 않습니다.

```sh
EINK_ROOT="$PWD"
EINK_CLI='/Applications/Arduino IDE.app/Contents/Resources/app/lib/backend/resources/arduino-cli'
EINK_CONFIG="$EINK_ROOT/.local/arduino-cli.yaml"
EINK_FQBN='esp32:esp32:esp32s3:USBMode=hwcdc,CDCOnBoot=cdc,MSCOnBoot=default,DFUOnBoot=default,UploadMode=default,FlashMode=qio,FlashSize=16M,PartitionScheme=app3M_fat9M_16MB,PSRAM=opi,CPUFreq=240,LoopCore=1,EventsCore=1,DebugLevel=none,UploadSpeed=115200,EraseFlash=none'

"$EINK_CLI" --config-file "$EINK_CONFIG" compile \
  --fqbn "$EINK_FQBN" \
  --library "$EINK_ROOT/.local/libraries/LilyGo-EPD47" \
  --build-path "$EINK_ROOT/.local/build/bw_animation" \
  --warnings default firmware/bw_animation

"$EINK_CLI" --config-file "$EINK_CONFIG" board list
EINK_PORT='<현재 조회하고 대상 확인한 포트>'
"$EINK_CLI" --config-file "$EINK_CONFIG" upload \
  --fqbn "$EINK_FQBN" --port "$EINK_PORT" \
  --input-dir "$EINK_ROOT/.local/build/bw_animation" \
  --verify firmware/bw_animation
```

아래 명령은 첫 정상 정적 이미지 시험으로 복귀할 때만 실행합니다. 복귀하면 부팅당 그림 3장 출력 시험이 다시 한 번 실행됩니다.

```sh
"$EINK_CLI" --config-file "$EINK_CONFIG" upload \
  --fqbn "$EINK_FQBN" --port "$EINK_PORT" \
  --input-dir "$EINK_ROOT/.local/build/first_image" \
  --verify firmware/first_image
```

출고 상태로 돌아가야 하면 [전체 백업 복구 절차](환경-및-검증.md#복구-절차)를 따릅니다. 펌웨어 복귀는 패널 잔상이나 손상의 회복을 보장하지 않습니다. 이번 단계에서 복귀·출고 복원은 필요해 실제 실행한 경우에만 별도 기록합니다.

## 실물 관찰과 깜빡임의 원인

사용자 관찰: “오른쪽으로 이동 하는거 인지는 했는데 검은 사각형 주위로 큰 사각형이 깜빡임이 심했음.” 큰 영역이 검게 바뀌는 과정을 인지할 정도로 느렸으며, 마지막 확인에서는 “멈췄고 깜빡임·잔상 없음”이라고 답했습니다.

작은 도형은 64×64이지만, 매 프레임 **640×400 시험 영역 전체**에 `epd_clear_area()`를 호출하고 그 영역 전체 버퍼를 다시 그립니다. 패널 전체 960×540을 매번 지우는 것은 아닙니다. 기본 영역 지우기는 검정 주사 4회·흰색 주사 4회를 한 묶음으로 4차례 수행합니다. 사용자가 본 큰 사각형의 반복적인 반전은 이 지우기 동작과 부합합니다. 이후 흰 배경과 작은 검은 사각형을 4비트 회색조 출력 경로로 그립니다.

종료 후 잔상이 없다는 관찰은 이번 짧은 시험의 결과입니다. 장시간 사용이나 다른 갱신 방식의 잔상·안전성을 뜻하지 않습니다. 외부 여백의 변화와 전압 파형은 별도로 관찰·계측하지 않았습니다.

## 발견한 제조사 지연 함수 결함

프레임 인덱스 0~3의 전원 켜기/끄기는 약 708/118µs였으나 인덱스 4~7에서는 약 8/8µs로 줄었습니다. 인덱스 8은 켜기 약 8µs·끄기 118µs였고 9~11에서는 약 707/118µs로 돌아왔습니다. 이는 정상적인 속도 향상으로 해석하지 않습니다.

고정한 제조사 소스 `src/ed047tc1.c:104`의 `busy_delay()`는 CPU 사이클 카운터에 지연값을 더한 목표를 `uint64_t`에 저장합니다. 반면 ESP32 코어 2.0.17의 `XTHAL_GET_CCOUNT()`는 `signed int`를 반환합니다. 비교 시 카운터 최상위 비트가 1인 음수 값이 큰 `uint64_t`로 변환돼 대기 조건이 즉시 거짓이 됩니다. 실제 빌드된 ELF에서도 목표값의 상위 32비트는 0, 비교값은 부호 확장되는 명령을 확인했습니다.

240MHz에서 카운터 한 주기의 약 8.948~17.896초 구간에 해당하며, 실측에서 짧아졌다가 복귀하는 패턴과 부합합니다. 영향은 `epd_poweron()`의 100+500+100µs, `epd_poweroff()`의 10+100µs 및 `epd_start_frame()`의 1µs 대기입니다. 화면 주사 시작 타이밍에도 영향이 있으므로 전원 시간만 제외하고 정상 성능이라고 판단할 수 없습니다.

호스트의 정수 변환 모의 검토에서도 500µs 요청이 `0x7ffffff0` 시작에서는 약 0.067µs, `0x80000000`·`0x90000000`·`0xfffffff0`에서는 즉시 종료됨을 확인했습니다. 장치에서 경계 시험을 추가한 것은 아닙니다. `panel_power=off`는 전원 끄기 함수가 반환한 뒤 출력한 표식이며 정상 전압 순서를 계측한 결과가 아닙니다.

드라이버 변경은 이번 승인 범위에서 제외돼 있어 원본을 보존했습니다. USB 전송·게임 연동 시험 전에 별도 계획에서 지연 계산을 최소 수정하고 경계값·실제 코드 경로를 검증해야 합니다. 갱신 방식 역시 매번 영역을 검정·흰색으로 지우는 비용을 줄일 수 있는지 검토해야 하며, 무조건 지우기 호출을 없애거나 고속·무잔상을 보장하지 않습니다.

## 측정 해석
