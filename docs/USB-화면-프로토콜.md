# USB 화면 전송 계약 v3 (고정 점무늬 흑백 차분)

현재 호스트·펌웨어는 v3를 함께 사용한다. v1의 단순 문턱값 흑백과 v2의 실제 16계조는 Git 이력과 보존한 바이너리에 남아 있다. v3는 고정 점무늬·생명력 보정과 최신 ACK 보호를 사용하는 차분 시험이며 이전 버전을 거부한다. 게임·USB·패널은 각각 독립적으로 진행하고 USB는 ACK 이후에만 다음 프레임을 보낸다. 재전송·재접속·재시작은 자동으로 하지 않는다. Mac을 다른 게임 실행 보드로 바꿔도 아래 픽셀·패킷 계약을 공급하면 화면 구동부는 재사용할 수 있다. 새 보드의 실제 연동은 별도 검증한다.

## 최신 게임 화면

`SDLPOP_EINK_FRAME_PATH`가 지정된 경우에만 SDLPoP에서 추출한다. 320×200 RGB24 최종 합성 화면을 SDL 비차단 잠금으로 최신 슬롯에 복사하고 작업 스레드가 같은 디렉터리의 임시 파일을 닫은 뒤 rename한다. 메인 렌더링 스레드는 파일 I/O·USB·작업 스레드 완료를 기다리지 않는다. 정상 종료 때만 작업 스레드를 join한다.

PPM 바이트는 `P6\n# eink sequence N\n320 200\n255\n` 뒤 RGB 192,000바이트다. N은 1부터 증가하는 10진 정수이며 추출 중 빠진 번호는 허용한다. 작업 스레드는 종료 시 마지막 대기 화면까지 저장한다. 같은 출력 경로에 생산자는 하나만 둔다.

호스트는 정확한 크기·해상도·최댓값을 검사하고 매 선택 프레임에 다음 변환을 적용한다.

1. 기본 회색은 `((77*R+150*G+29*B)>>8)>>4`로 0=검정, 15=흰색이다.
2. 기본 생명력 영역 `0≤x<69, 194≤y<199`의 RGB `(228,0,0)`은 15, `(184,0,0)`은 12로 우선 매핑한다. 삼각형의 검정 빈 부분과 다른 위치는 이 보정을 받지 않는다.
3. 나머지 픽셀의 회색 1~13은 1단계 밝게, 0·14·15는 그대로 둔다.

4. 고정 Bayer 4×4 행렬 `[[0,8,2,10],[12,4,14,6],[3,11,1,9],[15,7,13,5]]`을 사용한다. 보정된 회색값을 g라 할 때 `g*32 < (2*행렬[y%4][x%4]+1)*15`이면 검정, 아니면 흰색이다. 0/15는 완전 검정/흰색이며 패턴은 화면 좌표에 고정하고 프레임 번호나 시간에 따라 바꾸지 않는다.

기본 게임 팔레트·HUD 위치를 전제로 한다. 전송은 행 우선, 행당 40바이트, 왼쪽 픽셀이 MSB, 1=검정·0=흰색이며 정확히 8,000바이트다. 최초 선택 PPM과 흑백 PGM(검정=0·흰색=255)을 로그 옆에 보존한다. 정지화면에서 확인된 밝기 보정값을 이용하지만 점무늬의 실물 가독성은 별도 평가한다.

## 호스트에서 보드로 보내는 패킷

모든 정수는 little endian. 헤더는 20바이트이며 Python 표기는 `<4sBBHIII`다.

| 필드 | 크기 | 값 |
| --- | --- | --- |
| magic | 4 | ASCII `EPK1` |
| version | 1 | 3 |
| type | 1 | 1=START, 2=FRAME, 3=STOP |
| reserved | 2 | 0 |
| session | 4 | 호스트가 생성한 0이 아닌 uint32 |
| sequence | 4 | START=0, 이후 1부터 순서대로 |
| length | 4 | START=1, FRAME=8000, STOP=0 |

헤더 뒤 payload와 CRC32 4바이트가 붙는다. CRC는 헤더 전체+payload의 IEEE CRC-32로 `zlib.crc32(data)&0xffffffff`와 같다. 시험 벡터 `123456789`=0xCBF43926. FRAME 총 크기는 8,024바이트다.

START payload는 최대 프레임 수 1~12를 나타내는 한 바이트다. 부팅당 한 START만 소비한다. FRAME sequence는 1부터 단조 증가하며 변경 없는 프레임도 한도에 센다. STOP은 다음 FRAME과 같은 예상 sequence를 쓰며 패널 접근 없이 종료한다. 헤더가 잘못되면 payload를 기다리지 않고 terminal 오류로 끝낸다. 수신 중 payload 바이트는 명령이나 magic으로 재해석하지 않는다.

## 보드 응답

ASCII 한 줄, LF 또는 CRLF. 필드는 공백으로 나눈 `key=value`, 줄은 최대 512바이트다. session/seq 등 정수는 10진수, crc만 소문자 8자리 16진수다.

- `USB_FRAME_READY version=3 panel=untouched` — 시작 전 1초마다. 호스트가 이 문구를 확인한 뒤 START를 한 번만 보낸다.
- `USB_FRAME_ACCEPT session=N max_frames=N` — 검증된 START. 메모리·CPU·20초 지연 검사를 수행한다.
- `USB_FRAME_DELAY_DONE status=pass|fail ...` — 기존 지연 선행 검사의 결과. 부가 진단은 `USB_FRAME_STATS`를 사용한다.
- `USB_FRAME_RX session=N` — 검사 통과·프레임 수신 가능. 여기 전에는 FRAME을 보내지 않는다.
- `USB_FRAME_ACK session=N seq=N crc=XXXXXXXX result=applied|unchanged rx_us=N display_us=N clear_us=N white_us=N black_us=N elapsed_us=N` — CRC는 FRAME 패킷 CRC. 화면 처리와 poweroff 완료 후 이전 프레임을 확정한 뒤 응답한다. 응답 전 연결을 최대100ms 확인하며 ACK 후 flush·연결 재확인 뒤 다음 RX 제한을 시작한다. 연결 확인 실패는 ack_connection 오류로 끝낸다. flush는 호스트 수신 보장을 뜻하지 않는다. `rx_us`는 해당 패킷 첫 바이트부터 CRC 수신까지, `display_us`는 렌더 처리 전체, clear/white/black은 최초 전체 지우기·검정→흰색·흰색→검정 호출, elapsed는 최초 panelon부터다. 후속 프레임 clear_us는 0이며 없는 극성은 호출하지 않고 해당 시간은 0이다.
- `USB_FRAME_ERROR reason=CODE` — 오류. 추가 패널 접근·파싱·재동기화 없음.
- `USB_FRAME_DONE session=N reason=limit|stop|time_limit|error frames=N applied=N` — terminal 상태. 이후 START/FRAME을 받아도 다시 실행하지 않는다.

호스트는 ACCEPT·RX·ACK·DONE의 session/순서를 검증하고 예상하지 않은 ACK, ERROR, ACCEPT 뒤 READY/재부팅, 연결 종료, 응답 시간초과에 중단한다. ACCEPT 전에는 USB에 남아 있던 정확한 READY를 허용하되 START를 재전송하거나 대기 시간을 연장하지 않는다. ERROR 뒤 DONE이 없더라도 성공으로 처리하지 않는다. 종료 후 10초 동안 추가 실행·재부팅 로그를 관찰하며 STATS도 추가 응답으로 거부한다.

## 출력·실행 제한

- Serial begin 전 `setRxBufferSize(32768)` 결과를 검사한다. RX 준비/ACK 이후 한 프레임만 송신한다.
- 부팅·START·지연 검사만으로 패널 초기화·전원·지우기를 하지 않는다. 첫 완전한 FRAME의 길이·CRC·세션·순서 검사가 통과해야 접근한다.
- 첫 유효 화면은 모두 흰색이어도 반드시 전체 지우기를 한다. 이전 버퍼를 흰색으로 초기화하고 첫 그림의 검정 픽셀을 표시한다. 이후 변경 프레임은 검정→흰색, 흰색→검정 순으로 바뀐 픽셀만 구동한다. 변경 없는 화면은 전원도 켜지 않는다. 실제 회색 간 전환 파형은 만들지 않는다.
- 320×200 입력을 x=160,y=70에서 2×2로 확대한다. 드라이버용 4bpp 마스크는 최대 960×400, 192,000바이트이며 각 극성에서 바뀌지 않는 픽셀은 무동작 값이다. 검정→흰색 마스크는 기본 0, 해당 픽셀만 15이며 `WHITE_ON_BLACK`을 사용한다. 흰색→검정은 기본 15, 해당 픽셀만 0이며 `BLACK_ON_WHITE`를 사용한다. driver `f1607da`의 기존 `epd_draw_image`를 재사용하며 전체 960px 폭과 변경된 첫·마지막 행 사이만 전달한다. 좌우 여백도 무동작 값이다.
- 수신은 비차단·짧은 읽기를 누적하며 상한과 절대 시간을 검사한다. START는 첫 바이트부터 5초, FRAME/STOP은 RX_READY 또는 직전 ACK부터 5초 안에 전체 패킷을 받아야 한다.
- 최초 패널 전원 켜기부터 30초가 지나면 새 화면 처리를 시작하지 않는다. 수신 중에도 검사한다. 진행 중 드라이버 호출은 강제 중단하지 않으며 시작한 프레임은 필요한 두 패스와 전원 끄기까지 마친다.
- 호스트는 ACK 뒤 최소 250ms 간격을 두고 최신 PPM을 읽는다. 한 세션은 1~12장이다. 정지화면 확인을 마친 뒤 첫 연속 시험은 사용자 관찰 준비 답변을 받아 시작한다.
- 타임아웃·길이·CRC·순서·할당·CPU/지연 검사 오류에서 전원 끄기 상태로 terminal 종료한다. 호스트도 자동 재전송하지 않는다. 종료 정리를 추가로 수행하지 않으며 마지막 그림을 유지한다. DONE 뒤 다시 패널을 구동하지 않는다.

ACK 시간은 드라이버 함수의 완료 기준이며 실제 e-paper 광학 전환 완료나 게임 입력 지연을 직접 측정한 값은 아니다.

첫 화면의 전체 지우기에는 깜빡임이 있다. 후속 프레임의 큰 깜빡임 감소와 실제 게임 가독성·잔상·처리 시간은 실물로 확인한다. 기존 사각형 시험 결과만으로 게임 속도를 보장하지 않는다. 게임 로직은 계속 진행하므로 표시 사이의 중간 게임 프레임은 건너뛴다.

## 선택적 v9 방 전환 정리 (2026-10-06)

- 게임 환경 `SDLPOP_EINK_SCENE=1`일 때 PPM sequence 주석 다음에 `# eink scene <level> <room>`을 기록한다. level0~15/room1~24, RGB와 같은 최신 슬롯/원자 파일이다. 방 전환·전체 재그리기 미완성 화면은 내보내지 않는다. 미지정 시 기존 PPM 유지.
- 호스트 `--interactive --room-refresh --normal-gap-2ms --normal-direct13`은 v9 READY의 `room_refresh=1`을 요구한다. PPM의 메타데이터가 없거나 범위 밖이면 거부한다. 마지막 ACK 화면의 `(level,room)`과 비교하며 첫 장은 초기 정리만 수행한다.
- v9는 v8 START/길이/상한을 유지하고 20바이트 헤더의 기존 reserved LE16에 bit0=`해당 프레임 표시 전 정리`를 추가한다. FRAME/PATCH/RLE/LZ의 sequence>1에서만 허용하며 다른 비트, START/STOP/첫 장의 플래그는 거부한다. 플래그도 패킷 CRC 보호 범위다. v7/v8은 reserved=0 유지.
- 완전 패킷 CRC와 압축 복원을 먼저 검증한 뒤 정리한다. 특히 PATCH는 이전 실제 표시 입력에서 복원한 후 기준 버퍼를 흰색으로 지운다. 새 방/30초 주기가 겹쳐도 한 번만 정리하고 같은 입력 전체를 재표시한다.
- `PAINTER_USB_REFRESH session=... seq=... reason=room|periodic|both`를 TIMING/ACK 전에 보낸다. 호스트는 요청 여부와 원인을 대조한다. 정리 후 같은 입력의 후속 PATCH는 중복 구동하지 않는다.
- v9 호스트는 매 장 정리되는 최악 조건까지 응답18128개(6000×3+128), 원본9317792바이트 상한을 둔다. 기존 개별 줄 제한·최대600초6000장·수신5초·구동5초·STOP/OFF 유지. 정리 구간은 일반 갱신 속도와 분리한다.
- 펌웨어는 기존 대화형 빌드 플래그에 `PAINTER_USB_ROOM_REFRESH`를 추가한다. 이전 빌드/프로토콜은 유지한다. 이는 방 전환 명암의 우회책으로 광학 합격은 실물 확인이 필요하다.
