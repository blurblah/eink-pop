# 16계조 게임 정지 화면 한 장

실행일: 2026-09-20, Asia/Seoul. 승인: 16계조 미리보기 확인 후 “예시 좋아. 그대로 화면에 올려줘”.

## 현재 상태

사용자가 확인한 미리보기와 같은 이미지 데이터를 담은 `gray_game` 정지 화면 펌웨어를 업로드하고 한 번 실행했다.199표본 지연 검사와 한 장 처리·전원 끄기·종료 뒤10초 확인을 통과했다. 보드는 최종 화면을 유지하며 실제 가독성에 대한 사용자 관찰 답변을 기다린다.

## 이미지와 표시 조건

- 입력: 실제 SDLPoP에서 추출한320×200 RGB, source sequence46. PPM SHA-256 `322cf921b76b6447d227a5cdc27bdedf78f51abef8c3a0d757d2d72c26eb385e`.
- 변환: 휘도 `(77R+150G+29B)>>8`의 상위4비트. 점무늬·대비 보정 없음. 0=검정,15=흰색, 짝수x 하위 nibble.
- 원본4bpp 데이터32,000바이트의 SHA-256 `ae8662b33fb9068160ba1b314b4fbd014801275dd2bcd70fe00cc3f833d50aaa`.
- `firmware/gray_game/src/game_image.h`에 이미지 데이터를 보존한다. 사용자에게 보여 준 `artifacts/usb-game-gray16-preview.png`와 확대 후256,000픽셀이 모두 일치했다. PNG CRC도 확인했다.
- 전체 패널960×540 중 x160,y70에640×400으로2배 정수 확대한다. 전체960폭×400행 버퍼192,000바이트의 좌우 여백은 흰색이다.
- 드라이버에는 `{0,70,960,400}` 영역을 전달한다. 영역의 행 간격480바이트와 버퍼의 행 간격을 일치시키고 좌우 패딩 경로를 피한다.

## 실행 제한

부팅 직후에는 `GRAY_GAME_READY`만 반복 출력하며 패널을 초기화하지 않는다. 정확한 `RUN\n` 또는 `RUN\r\n` 한 번을 받으면 즉시 실행 권한을 소비한다. 할당·4바이트 정렬·CPU240MHz·약20초 지연 검사 통과 후 전체 지우기1회, `epd_draw_grayscale_image()`1회, 전원 끄기 순서로 종료한다. 성공·실패 모두 같은 부팅에서 다시 출력하지 않는다. 화면은 마지막 상태를 유지한다.

이는 이미지를 펌웨어에 포함한 정지 화면 시험이다. 기존 USB v1의1비트 패킷·호스트·펌웨어 및 SDLPoP 추출기는 변경하지 않았다. 회색조 연속 게임 전송·회색 간 차분 파형은 구현하지 않았다.

## 빌드와 보존

Arduino CLI1.5.1, 프로젝트 ESP32 코어2.0.17, ESP32-S3·16MB Flash·OPI PSRAM·240MHz의 기존FQBN을 사용했다. 드라이버 기준은 `f1607dab2df95295e6b50fc0e44c4c092a13938f`이며22개 컴파일 단위가 모두 `repos/LilyGo-EPD47` 경로다. 기존 `round` 선언 경고 외 새 경고는 없었다.

- 프로그램311,521바이트, 전역 변수19,440바이트.
- 앱 파일311,888바이트, SHA-256 `08931ac61c28249bed1d23ed07aaa1165abdf1b87a948be54d9e502d5e199648`.
- 출고16MB 백업과 직전 `usb_frame` 앱281,600바이트의 크기·SHA-256을 기존 기록과 대조했다. 실제 복원은 하지 않았다.
- 원본 빌드 로그와3개 바이너리 manifest는 `artifacts/logs/gray-game-build*`에 보존한다. 기기 식별자·백업·빌드는 커밋하지 않는다.

빌드·업로드의 도구 경로와FQBN은 [환경 문서](환경-및-검증.md)를 따른다. 스케치는 `firmware/gray_game`, 빌드 디렉터리는 `.local/build/gray_game`, 라이브러리는 `repos/LilyGo-EPD47`을 명시한다. 업로드 대상 포트는 매번 조회하고 원본 장치와 대조한다. 같은 스케치를 다시 부팅해도 시작 명령 전 화면은 바뀌지 않는다.

## 결과 해석과 복귀

Mac의0~255 명도와 실제 패널의16계조 광학 대비는 동일하다고 보장하지 않는다. 그리기 함수 반환 시간은 실제 화면 전환 완료 시간이나 게임fps가 아니다. 첫 전체 지우기 시간도 분리해 기록한다.

오류 시 추가RUN·재시도를 하지 않는다. 기존 다운로드 모드 중단 절차를 사용하며 필요 시 보존한USB 앱으로 복귀한다. 현재 한 장을 표시한 뒤 자동으로 다른 펌웨어를 덮어쓰지 않는다.

`python3 tests/test_gray_game.py`의11개 시나리오가 clang++ ASan·UBSan으로 통과했다. 실제 스케치·이미지를 포함해64,000원본 픽셀의2×2 확대와128,000여백 픽셀, 버퍼 경계·메모리 해제, RUN 분할·CRLF·잘못된 줄·초과길이·재실행 차단을 검사했다. 할당·정렬·CPU와 선행 지연 검사 실패에서는 패널 접근이0회였다. 정상 경로는 초기화·전원 켜기·전체 지우기·회색 그리기·전원 끄기 각각1회다. 이는 논리·메모리 검증이며 물리 회색 정확도 검증은 아니다.
