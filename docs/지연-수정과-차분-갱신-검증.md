# 지연 수정과 바뀐 픽셀 갱신 검증

실행일: 2026-09-19, Asia/Seoul. 승인 근거는 [계획](../.Codex/plans/PLAN-20260919-1938-driver-delay-and-delta-update.md)과 저장소 처리 뒤 나머지를 계획대로 진행하라는 사용자 지시다.

## 현재 상태

저장소 이관·기존 변경 커밋, 드라이버 수정·호스트 검증·빌드와 한 차례 장치 시험을 마쳤다. 장치의 500µs 요청 199개가 모두 501~505µs로 측정됐으며 부호 구간 양쪽에서 조기 종료가 없었다. 화면은 12프레임을 12.203039초에 완료했고 종료 후 약 10초 동안 추가 실행 로그가 없었다. 사용자 실물 관찰은 확인 중이다.

이전 시험은 매 프레임 640×400 영역을 지워 큰 반전이 보였고, 제조사 지연 함수의 일부 대기 생략도 발견됐다. 이번에는 지연 결함을 수정한 뒤 바뀐 픽셀만 구동했다. 성능·깜빡임의 최종 판단은 아래 소프트웨어 수치와 사용자 관찰을 구분해 기록한다.

## 수정·표시 방식

`busy_delay()`의 signed 카운터와 64비트 목표값 비교를 unsigned 32비트 경과량 비교로 바꿨다. 함수의 IRAM 속성·호출처·240MHz 환산·전원 순서는 유지했다. 같은 형태로 보이는 `epd_driver.c`의 다른 대기는 주석이므로 변경하지 않았다.

4bpp의 기존 `WHITE_ON_BLACK`·`BLACK_ON_WHITE`와 기본 15단계 파형을 사용한다. 첫 전체 지우기 후에는 영역 지우기를 반복하지 않는다.

| 항목 | 설정 |
| --- | --- |
| 전달 영역 | x=0, y=238, 960×64 |
| 버퍼 | PSRAM 30,720바이트, 행당 480바이트 |
| 도형 | 64×64, 전역 x=184+48×인덱스(0~11) |
| 첫 프레임 | 전체 F, 도형만 0 → 검정 출력 |
| 흰 복원 | 전체 0, 떠나는 왼쪽 48×64만 F → 흰색 출력 |
| 검정 추가 | 전체 F, 들어오는 오른쪽 48×64만 0 → 검정 출력 |
| 유지 부분 | 겹치는 16×64와 주변 픽셀은 두 패스 모두 무동작 |
| 제한 | 최초 전체 지우기 1회, 최대 12프레임·그리기 23회, 매 프레임 250ms 대기 |
| 시간 | 최초 패널 전원 켜기부터 30초 이후 새 프레임을 시작하지 않음 |

행 전체를 전달하는 이유는 작은 Rect에 대한 제조사 흰색 모드의 여백 패딩을 피하기 위해서다. 마스크 바깥의 값은 LUT에서 무동작으로 변환되므로 행 전체를 색으로 채우는 뜻이 아니다. 두 패스 사이에 잠깐 폭 16픽셀의 중간 도형이 보일 수 있다. 실제 흰색 복원·잔상·깜빡임 감소는 실물 관찰로 판단한다.

## 실행과 재현

프로젝트 루트에서 실행한다. 새 드라이버 경로를 명시하며 기존 빌드 디렉터리를 덮어쓰지 않는다.

```sh
EINK_ROOT="$PWD"
EINK_CLI='/Applications/Arduino IDE.app/Contents/Resources/app/lib/backend/resources/arduino-cli'
EINK_CONFIG="$EINK_ROOT/.local/arduino-cli.yaml"
EINK_FQBN='esp32:esp32:esp32s3:USBMode=hwcdc,CDCOnBoot=cdc,MSCOnBoot=default,DFUOnBoot=default,UploadMode=default,FlashMode=qio,FlashSize=16M,PartitionScheme=app3M_fat9M_16MB,PSRAM=opi,CPUFreq=240,LoopCore=1,EventsCore=1,DebugLevel=none,UploadSpeed=115200,EraseFlash=none'

python3 tests/test_busy_delay.py
python3 tests/test_bw_delta.py

"$EINK_CLI" --config-file "$EINK_CONFIG" compile \
  --fqbn "$EINK_FQBN" \
  --library "$EINK_ROOT/repos/LilyGo-EPD47" \
  --build-path "$EINK_ROOT/.local/build/bw_delta" \
  --warnings default firmware/bw_delta
```

업로드는 현재 포트·원래 장치와의 동일성·백업·앱 해시를 확인한 뒤 수행한다.

```sh
"$EINK_CLI" --config-file "$EINK_CONFIG" board list
EINK_PORT='<현재 조회하고 대상 확인한 포트>'
"$EINK_CLI" --config-file "$EINK_CONFIG" upload \
  --fqbn "$EINK_FQBN" --port "$EINK_PORT" \
  --input-dir "$EINK_ROOT/.local/build/bw_delta" \
  --verify firmware/bw_delta
```

이번 스케치는 부팅만으로 패널을 구동하지 않는다. 115200 직렬 연결에서 준비 로그를 확보한 후 `RUN` 한 줄을 한 번 보내야 시작한다. 먼저 패널 초기화 없이 20초간 실제 지연 함수의 500µs 요청을 검사하며, 카운터의 두 부호 구간에서 충분한 cycle을 기다린 경우에만 패널 시험을 시작한다. 할당·주파수·코어·지연 검사 실패 시 패널을 초기화하지 않는다. 시험 종료 후 추가 `RUN`을 보내도 다시 출력하지 않는다.

각 시간 제한은 다음 작업 시작을 막는 소프트웨어 조건이다. 드라이버 내부 정지를 강제로 끊지는 못한다. Mac은 시작 후 최대 90초 관찰하고 오류·재시작·미종료 시 다운로드 모드로 정지시킨다. 정상이면 종료 후 최소 10초 동안 추가 갱신이 없는지 보고 직렬 포트를 닫는다. 임의 반복 시험은 하지 않는다.

## 장치 지연·종료 결과

검사 중 CPU는 core 1·240MHz를 유지했다. 120,000cycle 요청의 측정 범위는 120,021~120,999cycle이고, 마이크로초 측정은 501~505µs였다. 각 표본의 시작·종료를 감싸는 측정 오버헤드를 포함한다. 카운터 부호가 0인 표본 110개와 1인 표본 89개 모두 요청보다 짧게 끝나지 않았다. 실제 카운터 값을 인위적으로 변경하지 않았다.

패널 전원 켜기 함수는 매 프레임 707~708µs, 끄기는 118µs였다. 이전에 관찰된 약 8µs로의 급감은 이번 시험에서 나타나지 않았다. 이는 함수 호출 시간이며 전원 레일 전압이나 실제 전환 순서를 계측한 결과는 아니다.

초기 전체 지우기 호출은 1,358.589ms였다. 첫 프레임은 검정 출력 한 번이라 약 341.537ms 처리했고, 이후 11프레임은 흰 복원·검정 추가 두 번으로 각각 약 682.12ms 처리했다. 첫 프레임 뒤의 시작 간격은 약 591.415ms, 그 다음부터는 약 932.000ms였다. 전체 시작 간격 평균에는 짧은 첫 처리 구간이 섞이므로 안정된 갱신 간격과 구분한다.

전체 화면 시험 12.203039초에는 초기 전체 지우기와 각 250ms 대기가 포함된다. 지연 검사 약 20초는 별도다. 최종 사각형 좌표는 x=712, y=238이며, 마지막 그림을 유지하고 전원 끄기 함수가 반환한 뒤 추가 화면 갱신을 하지 않았다. 실물 상태는 사용자 관찰과 별도로 기술한다.

- `artifacts/logs/bw-delta-runtime.log`: 시작·지연 표본 199개·프레임 12개·종료·통계 원본.
- `artifacts/logs/bw-delta-observation.json`: RUN 1회와 호스트 관찰 시각·종료 후 시간.
- `artifacts/logs/bw-delta-build-identity.json`: 실제 소스 커밋·드라이버 커밋·스케치 해시·FQBN.
- `artifacts/logs/bw-delta-measurements.json`: 원본 로그 해시, 재계산 통계와 34개 검증 결과.

이번 실행에서는 오류 중단·펌웨어 복귀·출고 백업 복원을 수행하지 않았다. 시험이 끝난 펌웨어는 대기 상태이며, 다시 부팅해도 RUN 명령 없이는 패널을 구동하지 않는다.

## 복귀와 한계

정지가 필요하면 다음 실행을 시작하지 않고 원인을 기록한다. 원본 전체 백업 복구는 [기존 복구 절차](환경-및-검증.md#복구-절차)를 사용한다. 첫 정적 이미지 바이너리에도 원본 지연 함수가 있으므로 그 펌웨어로 돌아가는 것을 결함 수정 상태로 부르지 않는다. 이번 단계에서 실제 복귀·복원을 한 경우만 실행했다고 기록한다.

부분 구동은 짧은 시험이라도 잔상·깜빡임 위험이 있다. 호스트 검증이나 드라이버 함수 반환은 패널 전압·물리적 정착 시간·장시간 안전성을 측정한 것이 아니다. 제조사의 [부분 갱신 주의사항](https://lilygo.cc/products/t5-4-7-inch-e-paper-v2-3)을 유지하며 별도 파형 조정·1bpp 고속 모드·USB 픽셀 전송은 이번 범위에 포함하지 않는다.
