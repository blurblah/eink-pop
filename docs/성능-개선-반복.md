## 다음 재개 방향 — 2026-09-29 종료 후 검토

사용자는 오늘 작업을 종료하고 다음 재개 때 가능성이 가장 높은 방향을 제시해 달라고 요청했다. 이 절은 다음 작업의 제안이며 새 구현·업로드·실물 시험을 실행한 기록이 아니다. 기존 장치 마지막 상태와 사용량 수치는 재조회하지 않았으므로 위 표의 마지막 확인값을 유지한다.

**우선 제안은 FAST의 밝기 전이별 잔상 원인을 좁히고, 문제가 큰 전이만 선택적으로 보정하는 접근이다.** 현재 NORMAL은 주사·대기만176.290ms여서 같은 구동 시간을 유지하는 계산/전송 최적화로100ms에 도달할 수 없다. FAST는95.265ms로 속도 출발점이 유리하지만, 잔상이 일부 전이에 집중되는지와 보정 후100ms를 유지할 수 있는지는 미검증이다. 성공 확률을 수치로 제시하거나 잔상 없는10장/초를 약속하지 않는다.

다음 재개 시 제시할 순서:

1. Git·사용량·기존 측정 자료를 확인한다. 사용자 종료 요청을 한도 초기화만으로 해제하지 않는다. 실제 파형 변경의 계획·승인 범위는 구현 전에 확인한다.
2. 정상 NORMAL을 화질 기준으로 보존하고, FAST의4명도 간12개 변경 전이에 대한 제한 시험을 설계한다. 반복 순서에 따른 잔상도 구분한다. 우선 카메라/스캐너 등 광학 측정 수단의 가용성을 확인하고 고정 노출·위치·관측 시점에서 기준 대비 밝기 오차와 이전 도형 흔적을 비교할 방법을 정한다. 측정 수단이 없으면 자동으로 잔상 개선을 판정할 수 없음을 명시하고 필요한 관찰만 묶어서 요청한다.
3. 문제가 큰 전이가 확인되면 해당 구동만 소폭 보정하는 후보의 시간 예산을 먼저 계산한다. 특정 전이의 주사 추가가 화면 전체 주사 수를 늘릴 수 있으므로 픽셀 수가 적다는 이유로 비용이 작다고 가정하지 않는다. 근거 없는 전압 변경은 하지 않는다.
4. 후보별로 잔상 감소·명암 유지·추가 시간을 함께 비교한다. 제한 시험과 정리/OFF를 유지하고, 유망한 후보만 같은 게임 클립과 최신 입력에서 검증한다. 평균100ms·p95 125ms 목표와 기존 품질 조건을 모두 충족해야 채택한다. 광학 허용 오차는 측정 재현성과 NORMAL 기준을 확인한 뒤 실행 전에 기록하며 사후에 합격선을 낮추지 않는다.

FAST는 평균 목표까지 약4.7ms 여유뿐이다. 보정에 더 긴 구동이 필요하면100ms 목표를 유지하지 못할 수 있다. 그 경우 중간 속도/화질 후보의 결과를 별도로 보고하고 목표 달성으로 처리하지 않는다. 이 접근은 NORMAL 일반 최적화보다 우선할 근거가 있지만 H716의 물리적 한계나 최종 성공을 확정한 것은 아니다. 다음 파형 검토는 high 수준을 유지하는 편이 적절하며, 단순 구현·기록 단계로 바뀌면 추론 수준을 낮출 수 있는 시점을 사용자에게 먼저 알린다.

## 목표와 판정

2026-10-05 최신 승인: 아래100ms 목표는 과거 목표다. 사용자는 속도를 일부 양보한 잔상·화질 개선과 마지막 제한 비교를 승인했다. 이번33회의 조건·판정은 마지막 시작 기록을 우선한다. 과거 목표 달성으로 소급 표기하지 않는다.

기존 개발 인계의 표시 목표는 10~12장/초다. 이번 최소 목표는 **변경된 게임 화면의 실제 완료 응답 간격 평균 100ms 이하(10장/초 이상), p95 125ms 이하**다. 목표를 현재 성능에 맞춰 낮추지 않는다.

- 640×400 게임 영역, 320×200 원본, NORMAL 4명도 기준으로 비교한다. 화질·해상도를 낮춘 후보는 별도 결과이며 같은 목표를 달성했다고 처리하지 않는다.
- 완료 간격은 호스트의 단조 시계 ACK 수신 시각 차이다. 처음 전체 정리/초기화는 정상 구간 평균에서 제외하고 별도로 보고한다. 각 12장 시험의 11개 간격에서 p95는 nearest-rank 방식으로 산출한다.
- 정지 화면 반복이나 미구동 ACK로 속도를 부풀리지 않는다. 전송 원본·CRC·실제 변경·드라이버 완료 주기를 검증하고, 무변경 표본이 있으면 분리 보고한다.
- 목표 후보는 이동·점프·전투를 포함하는 고정 입력으로 비교하고, 최신 프레임 선택 경로에서도 측정한다. 녹화 재생·호스트 단독 벤치마크만으로 실시간 목표 달성을 선언하지 않는다.
- ACK 속도는 광학 fps나 버튼 입력 지연이 아니다. 원본 프레임 선택 간격, 수신/준비/paint 시간, 프레임 읽기~ACK 시간도 함께 기록한다.
- 사용자 확인 없이 가능한 것은 동일 입력/출력·구동 조건을 보존하는 최적화다. 파형·주사 간격·전압을 바꾸면 이전의 “잔상 없음” 평가를 승계할 수 없다. 광학 미검증 후보로 구분하고 사용자 확인을 매 회 요구하지 않는다.

## 종료 조건

1. 위 성능 목표와 검증 조건을 충족하면 목표 달성으로 종료한다.
2. **조회 가능한 Codex 한도 중 하나라도 잔여량이 60% 미만이면 개선 반복을 중단한다(2026-10-05 사용자 변경).** `remaining = 100 - usedPercent`. 정확히 60%는 사용자 조건상 중단 경계 미만이 아니다. 미제공 한도를 0% 또는 충분한 잔여량으로 가정하지 않는다.
3. 사용자 중단 요청, 장치 오류, 복구/전원 종료 확인 실패가 있으면 즉시 해당 실행을 중단한다. 목표 미달을 성공으로 바꾸지 않는다.
4. 사용량 조회가 실패하면 새 비용 큰 회차·업로드를 시작하지 않고 재조회한다. 확인 없이 계속 진행하지 않는다. 리셋 크레딧은 사용하지 않는다.

한도는 매 회 시작/종료 및 긴 회차의 빌드·업로드·실측 경계마다 조회한다. 조회 사이의 사용량 변화를 완전히 실시간 감시할 수는 없다. 중단 조건 도달 시 진행 중 장치를 정상 종료하고 결과·복구 상태·다음 작업을 저장하는 정리만 수행한다.

## 사용자 개입·성공 판정 정책 — 2026-10-04 최신 지시

- 사용자는 모든 확인을 거부한 것이 아니다. 중간 후보는 자동 수치 개선·검증으로 걸러내고, 속도·정합성·안정성 기준을 통과한 최종 후보를 사용자가 확인하는 방식이다. 매 후보마다 육안 답변이나 “진행”을 기다리지 않는다. 중간에는 사용자 없이는 판단할 수 없는 필수적인 사항만 예외로 묻는다.
- 성공은 실제 문제 해결과 수치 목표의 동시 충족이다. 현재2쌍 후보는 약95ms여도 이동 잔상이 남으므로 실패다. 느린 장면/지연 표본을 제외하거나, 정지·무변경 프레임으로 수치를 높이거나, 해상도/명도를 줄이거나, 배경을 어둡게 해 잔상을 가리는 방식을 같은 목표의 성공으로 인정하지 않는다.
- 이동·점프·전투·넓은 장면 변경과 최신 입력 경로를 포함한다. 평균과p95, 원본 건너뜀, 실제 변경·구동, CRC/복원, 종료/OFF를 함께 검증한다. 계측 빌드는 비계측 빌드와 구분한다. 최종 육안에서 잔상/명암/가독성/깜빡임 문제가 남으면 속도가 좋아도 실패다.
- 자동 광학 장치가 없으므로 새 파형의 잔상 제거 여부를 ACK·시뮬레이션·이전 사진으로 인증할 수 없다. 이 때문에 중간 작업을 멈추지는 않되, 광학 미검증 상태를 명시한다. 근거 없는 파형을 무한 반복하지 않는다. 추가 전압 변경이나 시험 상한 확대는 하지 않는다.
- 모든 반복에서 기존 목표/종료 조건/로컬 커밋·push 금지 조건을 유지한다. 현재 사용자가 제공한 사진과 관찰은 충분하므로 더 질문하지 않고 이력·구동 분석을 진행한다.

## 개선 우선순위와 알려진 한계

1. 호스트 변환·무손실 행 패치·증분 확대·드라이버 재탐색 제거·부분 복사를 채택했다. 같은 입력의 완료 간격은275.362→208.155ms로 약24.4% 감소했다. 실제 게임 경로와 입력이 다른 수치를 섞어 개선율을 만들지 않는다.
