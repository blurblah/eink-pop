## 기존 변경 이관과 보존

- `/Users/blurblah/workspace/SDLPoP`의 기준 HEAD에서 독립 복제한 뒤, 미커밋 변경을 별도로 적용했습니다. 이관 내용은 `src/common.h`의 `<strings.h>` 추가 한 줄입니다.

- 원래 SDLPoP의 HEAD·브랜치·Git 상태·diff·파일 해시를 전후 대조했습니다. 원래 `master`와 미커밋 수정은 그대로이며 원본에서 checkout·reset·수정하지 않았습니다.

## 작업과 커밋 순서

현재 상태는 프로젝트 루트에서 확인합니다.

```sh
git status --short
git submodule status
git -C repos/LilyGo-EPD47 status --short --branch
git -C repos/SDLPoP status --short --branch
```

수정한 하위 저장소에서 먼저 검증·커밋하고, 상위에서 해당 경로를 `git add`해 사용 커밋을 갱신한 뒤 관련 문서와 함께 커밋합니다. 드라이버 빌드는 `--library "$PWD/repos/LilyGo-EPD47"`를 사용합니다. 과거 시험의 명령과 바이너리는 당시 드라이버를 근거로 한 기록이므로 자동으로 최신 경로·결과로 바꾸지 않습니다.

`git submodule update`는 기록된 커밋으로 checkout하며 작업 브랜치를 분리할 수 있습니다. 이 컴퓨터에서는 이미 만든 작업 브랜치에서 개발하고, 기존 작업을 확인하지 않은 강제 update·reset이나 `--remote` 갱신은 하지 않습니다.

## 로컬 커밋의 보존 범위

**push는 실행하지 않습니다.** 따라서 SDLPoP 수정 `bbf16fc`·`53b2ff3`와 드라이버 수정 `86be1ba`·`f1607da`·`9b8dcdb`는 공식 GitHub 원격에 없습니다. 다른 환경에서 상위 저장소와 공식 URL만 받아서는 로컬 전용 하위 커밋을 복원할 수 없습니다.

현재 작업을 옮기거나 백업할 때는 상위 `.git/modules/`를 포함한 전체 저장소를 보존해야 합니다. 상위 커밋의 하위 SHA만 보관하고 로컬 Git 객체를 지우면 수정 이력을 잃을 수 있습니다. 원격 게시나 별도 배포는 사용자 지시가 있을 때 진행합니다.
