# 고속 드라이버와 Screen-4.7-S3 V2.4 호환성 검토

검토일: 2026-09-27. 실제 장치 기준: `Screen-4.7-S3 V2.4 2024-12-03`, ESP32-S3·16MB Flash·8MB PSRAM. 기존9b8dcdb 앱의12장 시험은 종료 상태로 유지했다. 이 조사에서는 장치에 접근하거나 펌웨어를 업로드하지 않았다.

## 결론

**EPD_Painter를 우선 검증한다. 현재 소스에 H716 전용 핀·전원·구동 데이터가 이미 있고, 현재 프로젝트 환경에서 원본 소스 그대로 컴파일·링크됐다.** “H716이 지원 목록에 없으므로 전용 구현도 없다”는 판단은 틀리다. README 지원 표가 실제 구현을 반영하지 못하고 있다. 다만 사용자의 V2.4 보드에서 실행·속도·화질을 검증한 것은 아니다.

FastEPD도 시프트 레지스터 기반 제어와 사용자 정의 패널 API가 있어 소프트웨어 적용 가능성이 있다. 그러나 포함된 T5 Pro 핀은 현재 보드와 다르며 H716 전용 데이터가 확인된 EPD_Painter보다 우선할 근거는 부족하다. 현 제조사 드라이버의 빈 행 RMT 호출 묶음 구현은 보류한다.

## 실제 핀·회로 대조

제조사 `src/ed047tc1.h`의 ESP32-S3 분기, EPD_Painter `src/EPD_Painter_presets.h:15`의 H716 설정, 제조사 회로도 `schematic/Screen-4.7-S3-V2.4 24-12-03.pdf`를 대조했다. PDF 전체와 U3/U7 상세를 렌더링해 확인했고, 아래14개 GPIO는 코드에서 추출해 모두 일치함을 별도로 확인했다.

| 신호 | 현재 V2.4 / 제조사 드라이버 | EPD_Painter H716 | FastEPD T5 Pro 기본값 |
| --- | --- | --- | --- |
| D0~D7 | 8,1,2,3,4,5,6,7 | 동일 | 11,12,13,14,21,47,45,38 |
| CKH/CL | 41 | 41 | 10 |
| STH/SPH | 40 | 40 | 9 |
| CKV | 38 | 38 | 39 |
| 시프트 DATA | 13 | 13 | 2 |
| 시프트 CLK | 12 | 12 | 42 |
| 시프트 STR | 0 | 0 | 1 |

U3는74HCT4094D다. QP0=LE, QP1=전원 비활성, QP2=양전원 제어, QP3=음전원 제어, QP4=STV, QP6=MODE, QP7=OE의 비트 위치가 제조사·H716 구현과 대응한다. **QP5는 V2.4 회로에서 `PWR_EN`이며 두 코드에서는 scan direction으로 이름 붙어 있다.** 양쪽 모두 이를HIGH로 유지하므로 현재 동작값은 맞지만, 이름만 보고 스캔 방향 변경에 재사용하면 안 된다. 회로의 NC/저항 옵션과 실물 개별 부품 실장 상태까지 확인한 것은 아니다.

EPD_Painter의 `EPD_H716PowerDriver`는100µs 대기→음전원→500µs→양전원→100µs 순서를 사용한다. 전원 끄기는 양전원 OFF→10µs→음전원 OFF→100µs 후 제어·전원 비활성 처리다. 제조사와 기본 레일 순서·대기량이 대응한다. 시작 시 MODE/OE/STV 처리까지 완전히 같은 파형이라는 뜻은 아니다. 근거: [H716 전원 코드](https://github.com/tonywestonuk/EPD_Painter/blob/6335a149c5a9b3be4150880e0be64ef2529ba62a/src/epd_painter_powerctl.cpp#L321).

FastEPD의 `LilyGoEinkPower`와 `LilyGoRowControl` 역시 같은 비트 구성을 사용한다. `initCustomPanel(BBPANELDEF*, BBPANELPROCS*)`가 있어 핀 표와 제어 함수를 선택할 수 있지만, Pro 프리셋 그대로는 사용할 수 없다. 사용자 정의 초기화·행 전송·핀 선택을 실제로 빌드/실행한 상태도 아니다.

## 구동 방식에서 달라지는 부분

현재 제조사 경로는 흰색15단계와 검정15단계를 각각 주사하고 행마다 SDK I80·RMT를 호출한다. 동일12장 비교의 후속 표시 평균679.455ms는 이 구조의 결과이며 패널의 절대 한계가 아니다.

EPD_Painter의 현재 코드에서는 다음이 확인된다.

- SDK의 행별 `esp_lcd_panel_io_tx_color()` 경로 대신 LCD_CAM 레지스터와 GDMA를 직접 다루고 행 버퍼2개를 번갈아 사용한다.
- 상주 출력 태스크와 SIMD 변환을 사용한다. H716의 시프트 출력도 ESP32-S3 고속 GPIO 신호와 어셈블리를 사용한다.
- 기본4명도 FAST 경로는7단계이며 단계 사이 추가 대기를 하지 않는다. 어두워지는 픽셀과 밝아지는 픽셀을 별도 평면에서 계산한 뒤 같은 행 데이터로 합친다. 이후 중립 데이터540행 정리도 실행하므로 단순히7×행 시간만으로 완전한 프레임 시간을 계산하면 안 된다.
- NORMAL/HIGH·16계조·직접 전이 설정은 단계 수와 대기가 다르다. 직접 전이에서는 필요한 train 길이에 따라7단계보다 길어질 수도 있다. 따라서 “무조건7단계”라고 일반화하지 않는다.
- H716 전용4명도·16계조·직접 전이 데이터가 있다. 원본 주석은 **한 대의 H716**에서 보정한 값이라고 명시한다. 사용자의 패널·온도·전원에서 같은 명암이나 잔상 결과를 보장하지 않는다.

근거: [현재 출력 루프](https://github.com/tonywestonuk/EPD_Painter/blob/6335a149c5a9b3be4150880e0be64ef2529ba62a/src/EPD_Painter.cpp#L1243), [H716 구동 데이터](https://github.com/tonywestonuk/EPD_Painter/blob/6335a149c5a9b3be4150880e0be64ef2529ba62a/src/LilyGo_H716_Trains.h).

README의20fps와 오래된 구조 설명의14ms/70fps 표현은 서로 조건·설명이 일치하지 않는다. 현 소스는 작성 당시보다 바뀌었으며, 둘 다 현재 V2.4 실측 근거로 사용하지 않는다. 직접 DMA와 명도별 구동 변경 때문에 현재 경로보다 개선할 기술적 근거는 있지만 달성 속도는 아직 미정이다.

FastEPD는 S3에서 SDK I80 API를 사용하는 경로가 남아 있다. Pro 설정의20MHz와 다른 갱신 구조는 참고할 만하지만 EPD_Painter와 동일한 직접 DMA 방식이라고 분류하면 안 된다.

## 현재 환경의 빌드 결과

보드에 접근하지 않는 임시 raw-driver 스케치를 `.local/probes/painter_h716/`에 만들고, 기존 프로젝트 Arduino2.0.17·ESP32-S3·OPI PSRAM 설정으로 컴파일했다. GFX/LVGL이나 전역 라이브러리를 설치하지 않았다.

| 조건 | 결과 |
| --- | --- |
| 기본 C++11 + H716 전용 매크로 | Config 집합 초기화 변환 오류 |
| C++17 + H716 전용 매크로 | `autoDetectBoard()`의 `Probe` 미선언 오류 |
| C++17 + 매크로 기본값(AUTO 코드 포함), 생성자에 H716 설정 객체 명시 | **컴파일·링크 성공, 원본 라이브러리 수정 없음** |

성공 경로의 핵심은 다음과 같다.

```cpp
#include <EPD_Painter.h>
EPD_Painter panel(EPD_LILYGO_EPD47_H716_PRESET);
// begin() 전에 실행:
panel.setAutoShutdown(false);
panel.setQuality(EPD_Painter::Quality::QUALITY_FAST);
```

빌드 옵션은 `compiler.cpp.extra_flags=-std=gnu++17`이며 `--library .local/references/EPD_Painter`를 명시했다. 기본 AUTO 코드가 컴파일되더라도 생성자에 넘긴 H716의data_pins[0]이 유효하므로 현재 `autoDetectBoard()`는I2C 탐색 전에true를 반환한다. 핀 자동 탐색에 기대어 다른 보드를 고르는 방식이 아니다. 전용 매크로 실패는 정의된 프리셋에서 `Probe` 배열을 제외하면서 참조 함수는 계속 컴파일하는 소스 조건부 누락이다.

컴파일 출력: 프로그램324,573바이트, 전역35,296바이트. 앱 파일324,992바이트, SHA-256 `f10d01104635cabd2c1e49905e6ce91fe5a6d25f3c8378ce93aec67808cabcfc`. 동적 PSRAM·내부 RAM 할당의 성공까지 검증한 것은 아니다. 임시 스케치는 컴파일 탐침이며 장치 시험용으로 업로드하지 않는다.

## 실제 시험 전에 해결할 통합 조건

1. **자동 종료 기능은 끈다.** `setAutoShutdown(false)`를begin전에 적용한다. 현재 BootCtl의 일반 LilyGo 종료/USB 감지는BQ25896(0x6B)을 가정하지만 V2.4 회로 U9는HX6610S다. 자동 감지의0x6B 보조 후보도 이 보드에서 검증 근거로 사용하지 않는다. 패널 레일을 끄는 H716 powerOff와 보드 자체의 전원 종료는 별개다.
2. **완료 기준을 새로 연결한다.** `paint()` 반환은 버퍼 인수 시점이다. 실제 전송 완료 측정에는 `paintsCompleted()` 증가와 대기 상태, 마지막 LCD 작업까지 확인하는 제한 시험 제어가 필요하다. 제출 호출률을fps로 보고하지 않는다. 변경 없는 화면은완료 카운터를 늘리지 않는 점도 처리해야 한다.
3. **종료 시 패널 레일 OFF를 확인한다.** 라이브러리 `end()`는 출력 태스크/DMA 정리이며 전원OFF 호출 자체가 없다. 기본5초 idle 전원 관리는 별도 태스크다. 기존 시험의 종료 의미를 그대로 가정하지 말고, 확실한 완료·전원OFF 확인을 제공하는 작은 어댑터를 먼저 검증한다.
4. **첫 출력은 게임이 아닌 제한 패턴으로 한다.** 명시적 시작 전 패널 구동 없음, 흰색 정리·흑백 도형/4명도 확인, 제한 이동·최대 실행 시간, 마지막 정리·전원OFF로 끝나는 시험을 준비한다. 처음에는 작성자의 FAST4명도 조건을 고정하고 임의 파형·클록·보정값을 동시에 바꾸지 않는다.

현재 소스 대조에서 새 배선이나 다른 보드가 필수라는 장애는 찾지 못했다. 이 문장의 범위는 핀·제어 구조와 빌드까지다. 출력 파형의 전기적 적합성·체감속도·잔상·장시간 사용은 아직 미검증이다. 다음 단계는 EPD_Painter를 작업 브랜치/정본 저장소로 등록하고 위 제한 시험 어댑터를 호스트 검증·빌드하는 것이다. High를 유지하며 실물 관찰이 필요한 시점에만 사용자에게 요청한다.
