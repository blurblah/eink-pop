# 사각형 이동 경로 잔상 정리 진단

실행일: 2026-09-20, Asia/Seoul.

## 요청과 범위

사용자는 사각형 이동 경로에 잔상이 남아 있다고 보고했고, “이 문제부터 바로 확인해보자”라고 요청했다. 처음에는 리셋 버튼 자체 진단으로 잘못 이해했으나 사용자가 잔상 문제라는 뜻이라고 정정해 버튼 진단을 중단했다. 그 관찰은 [별도 기록](../.Codex/plans/PLAN-20260920-0219-reset-button-diagnosis.md)에 남기며 버튼 정상·불량 판정 근거로 사용하지 않는다.

직전 애니메이션은 마지막 화면을 유지하려고 종료 후 전체 정리를 하지 않았다. 이후 USB 펌웨어 업로드도 패널을 갱신하지 않았다. 따라서 누적 잔상과 부합하지만, 정리 후의 실물 확인 없이 제품 불량이나 영구 손상으로 판정하지 않는다.

이번 진단은 제조사 `epd_clear()` 한 번 후 흰 화면 유지다. 사용자는 “준비됐어요, 잔상 확인 시작”이라고 답했다. 게임 이미지·추가 부분 갱신·임의 파형 조정·반복 정리는 수행하지 않았다.

## 실행 조건

- 펌웨어: 기존 `usb_frame`, 앱 281,600바이트, SHA-256 `dfc935d48f86e67f66fc57136c6a15ffb7cce97109cc95447b514f7b274d74a0`. 추가 Flash 쓰기 없음.
- 드라이버: `f1607da`의 기존 전체 지우기. 영역 960×540, 기본 4사이클×(검정 4회+흰색 4회) 주사, 마지막 흰색.
- 호스트 입력: RGB 320×200 전체 흰색 PPM. 제품 변환 결과는 1bpp 8,000바이트 모두 0이며 SHA-256 `668946bab9868b28489bb906205ee1026045c8bcd3ca62a1bdf733c65491351b`.
- 세션: START 한도 1장, 첫 FRAME 한 장. 첫 전체 지우기 후 검정·흰색 추가 그림 호출 없이 poweroff·ACK·DONE·terminal.
- 사용자 준비 답변 이후 같은 USB 장치임을 다시 식별하고 실행. 호스트 원본 TX 8,049바이트는 START 25바이트+FRAME 8,024바이트뿐이며 각 CRC와 전부 흰색 payload를 재검증했다.

## 실물 결과

전체 지우기 뒤 사용자는 **“잔상이 완전히 사라졌어요”**라고 답했다. 따라서 이번 이동 경로 흔적은 제조사 전체 정리 한 번으로 제거되는 잔상이었음을 실물 관찰로 확인했다. 직전 부분 갱신 시험 종료 후 전체 정리를 하지 않아 흔적이 유지된 것으로 판단한다. 현재 관찰은 제품 불량이나 영구 손상을 뒷받침하지 않지만, 다른 하드웨어 상태까지 정상이라고 보증하는 검사는 아니다.

잔상 정리 확인은 완료했다. 부분 갱신 중 잔상이 다시 누적되는 문제와 게임 표시 적합성은 별도로 남는다. 리셋은 잔상 제거 명령이 아니며, 향후 시험도 정리 여부를 명시해 결과를 구분한다. 이 세션은 종료 후 추가 화면을 자동 출력하지 않았고 게임 이미지는 아직 보내지 않았다.

제조사 [제품 안내](https://lilygo.cc/products/t5-4-7-inch-e-paper-v2-3)는 장시간 부분 갱신의 잔상·손상을 경고한다. [공식 FAQ](https://wiki.lilygo.cc/products/t5-series/t5-e-paper/#faq)도 잔상 제거가 항상 보장되지는 않는다고 명시한다. 이 한 차례 결과만으로 장시간 부분 갱신 안전성이나 모든 하드웨어 상태를 보증하지 않는다.
